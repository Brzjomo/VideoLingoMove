# 上游 3.0.4 合并记录

> 本文记录把上游 `Huanshere/VideoLingo` main（`11048cc`，v3.0.4）值得合的部分
> 移植进 dev 的过程与结论。工作分支：`merge/upstream-3.0.4`（基于 `dev@1e0525e`）。
> 对照基线：合并前 dev 领先 65 个提交、落后 136 个；`git diff dev origin/main`
> 涉及 181 个文件。

## 一、职责与边界

- 本文**只**说明合并做了什么、拒绝了什么、以及为什么；不重复描述各模块的实现细节，细节见对应分层文档。
- 本合并**不包含环境大升级**：torch 仍为 2.1.2+cu118、whisperx 仍为 v3.2.0、
  streamlit 仍为 1.38.0。凡是与上游 torch 2.8 / whisperx 3.8 / Python 3.13 绑定的
  改动一律**不做**（见第七节）。
- 合并方式是**按特性挑选移植**，不是 `git merge`。

## 二、为什么不能直接 merge

- `git merge-base dev origin/main` = `b9fae43`（2024-12-13，2.0 之前）。dev 当初的
  "2.1.2" 来自上游非 main 血统（`8f31091` 的父提交 `1d71ed6` 不是 `origin/main`
  的祖先），是手动抄代码合进来的，因此 merge-base 差异会严重高估差异。
- 实测 `git merge-tree --write-tree dev origin/main` 产生约 48 个冲突文件，其中大量是
  `modify/delete`（dev 已删除的整条配音链路），且 `core/all_whisper_methods/*` 会被
  git 误判为重命名到 `core/asr_backend/*`。
- 上游 3.x 还做了大范围改名（`step*.py` → `_N_*.py`、`st_components/` →
  `core/st_utils/`、`prompts_storage.py` → `prompts.py`）。**dev 的目录结构不跟进**，
  只移植行为。

## 四、修复的 dev 真实缺陷

这些不是"上游更好"，而是 dev 当前代码确有 bug：

| # | 缺陷 | 位置 | 后果 |
| --- | --- | --- | --- |
| 1 | 侧边栏只写 `whisper.language`，不同步 `detected_language` | `st_components/sidebar_setting.py` | 5 处提示词与 `init_nlp` 读的是 `detected_language`，切换识别语言后提示词与实际语种不符、加载错 spaCy 模型 |
| 2 | 火山 ASR 分支从不写 `detected_language` | `core/step2_whisperX.py` | 自动检测模式下下游读到上一个视频的旧语言 |

| 4 | `find_video_files` 用 `not file.startswith("output/output")` 过滤 | `core/step1_ytdlp.py` | 两个方向都错：误删 `output tutorial.mp4`，误收 `OUTPUT_SUB.MP4` |

## 七、刻意不合的部分

| 上游内容 | 不合的理由 |
| --- | --- |
| 整条配音链路（step8~step12、`core/tts_backend/*`） | dev 已主动删除；上游的响度稳定/AAC/克隆参考等对字幕工具无意义 |
| 目录与命名重构 | 纯搬家，跟进只换来 181 处冲突面 |
| `api.llm_support_json` 改为布尔 | dev 现在是**模型白名单列表**，比全局布尔更精细，跟了是退步 |
| summary 的 JSON 键 `topic` → `theme` | dev 提示词与 `core/step4_2_translate_all.py` 都用 `topic` 且内部一致；照抄会让主题上下文恒为 `None` |
| `find_video_files` 严格化（文件数必须为 1） | dev 特意改为"多个取最新并告警"，是易用性改进 |
| FFmpeg GPU 自动检测 → 手动 `ffmpeg_gpu` | dev 的 `check_gpu_available()` 自动探测更好；上游把 `check_gpu_available()` 留成了死代码 |
| 删除 `check_hf_mirror()` | 对国内网络有价值；改成**进程内记忆化**（原来每分段 ping 一次两个域名） |
| `whisper.runtime` 改名 | dev 的引擎键是 `asr_engine`（whisper/volcano），改名会破坏既有配置 |
| `burn_subtitles` 键 | dev 用 `resolution: '0x0'` 表达同一开关，且实现更好（不写 1 帧黑占位视频） |
| i18n / `translations/` | dev 界面是纯中文；约 140 处字面量 + 7 份词表，收益低 |
| torch 2.8 / whisperx 3.8 / streamlit 1.49 / Python 3.13 | **环境大升级，本次明确排除** |
| `demucs` git 源改 PyPI | 与 torch 升级绑定，本次不动 |
| `setup_env.py`（uv）/ `runtime_libraries.py` | 前者绑 Python 3.13；后者只服务 TorchCodec 系 whisperx |
| `fileWatcherType = "none"` | **一度跟进后撤销**。上游的理由是"运行中写文件会触发 watcher 重跑"，但实测 Streamlit 的 watcher 只对**已导入的 Python 模块文件**注册监听（`watcher/local_sources_watcher.py` 为每个模块建 `PathWatcher(filepath, ...)`，非模块文件的变更会打出 `Received event for non-watched file` 并忽略），因此写 `output/`、重写 `config.yaml` 从来不会触发重跑。该设置在本项目无收益，代价是开发时改 `.py` 不再自动重载，故撤销并保持默认 `"auto"`。`toolbarMode = "viewer"` 保留（真实收益：隐藏 Deploy/开发者菜单）。 |

## 九、验证方式

```bash
# 回归测试（46 例，不需要重依赖）
python -m unittest discover -s tests -v

# 安装体检（缺少依赖时退出码为 1）
python installer.py --check

# 启动预检 + 日志（不实际启动时用 --no-log 观察预检输出）
python launch.py --no-log
```

已知验证边界（**未**验证的部分，如实记录）：

- 本机没有可用的项目 Python 环境（无 `videolingo` conda 环境，
  `json_repair` / `spacy` / `torch` 均未安装），因此**未做端到端跑通验证**；
  `tests/test_audio_extraction.py` 中依赖 `whisperX_utils` 真实调用的 3 个用例
  之所以能跑，是因为它们只依赖 `pandas`/`rich`/`ffmpeg`。
- 未验证 Streamlit 页面的实际渲染（`st.fragment` 进度面板、暂停/停止按钮）。
- 未验证火山 ASR 的真实请求链路（无凭据，且会产生费用）。
