# 合并后排错速查

> 用途：`merge/upstream-3.0.4` 合并后，**症状 → 最可能的原因 → 怎么确认 → 怎么办**。
> 背景与"为什么这么改"见 [`06-上游3.0.4合并记录.md`](06-上游3.0.4合并记录.md)；
> 更通用的报错检索见 [`05-常见故障排查.md`](05-常见故障排查.md)。

## 一、先跑这三条命令

```bash
python installer.py --check          # 环境体检；有错误时退出码为 1
python launch.py --no-log            # 启动前预检（缺包/缺 ffmpeg/端口占用），只打印不启动
python -m unittest discover -s tests -v   # 46 例回归测试
```

三条都通过仍出问题，再按下面的症状表定位。

## 二、症状速查表

| 症状 | 最可能的原因 | 怎么确认 | 怎么办 |
| --- | --- | --- | --- |
| 重新跑却不重新转录，或"改了设置没生效" | 命中了**转录缓存** `.cache/asr`（内容寻址，只有换模型/换引擎/改识别语言/换源文件内容才失效） | 页面上「♻️ 转录缓存（N 个条目）」展开项；或 `ls .cache/asr` | 页面按钮「清空转录缓存」；或 `whisper.cache: false` 关闭；或删掉 `.cache/asr` |
| 改了 `volcano_asr` 参数（模型版本/标点/DDC）但结果没变 | 命中了**火山二级缓存** `output/log/asr_results/` | 页面上「🔧 火山 ASR 结果缓存（N 个文件）」展开项 | 页面按钮「清空 ASR 结果缓存」。注意这**不是** `.cache/asr`，是两套 |
| 切换 Recog Lang 后提示词/断句仍用旧语种 | 已修（`get_source_language()` + `update_key` 同步）。若再现，说明三个键不一致：`whisper.language`、`whisper.detected_language`、`volcano_asr.language` | `grep -n "language" config.yaml`；跑 `tests/test_source_language.py` | 重新在侧边栏选一次识别语言（会同步写 `detected_language`）；火山引擎会同时同步 `volcano_asr.language`（选"自动检测"时写空串） |
| 字幕整体**逐渐**偏移（越到后面越晚） | 抽取命令缺 `-af aresample=async=1:first_pts=0` | 首选 `python -m unittest tests.test_audio_extraction -v`。辅助：`grep -c "aresample=async=1:first_pts=0" core/all_whisper_methods/whisperX_utils.py` 应为 **3**（2 条命令 + 1 行注释） | 两条命令（raw.wav 与 raw.mp3）都必须带该标志；注释里的出现不算数 |
| 音频输入跑完没有 `output_sub.mp4` | **预期行为**：音频输入只产出字幕文件，不做压制 | `cat output/input_manifest.json` 看 `type` 是否为 `audio` | 无需处理。字幕在 `output/` 下（`src.srt`/`trans.srt`/`<视频名>.srt`） |
| 上传音频后 `output/` 里只有一个音频文件、没有 `black_screen.mp4` | **预期行为**：已取消"把音频包成黑底视频"的做法 | 同上 | 无需处理。旧目录里的 `black_screen.mp4` 仍被兼容（`is_audio_placeholder()`） |
| 页面上没有"开始处理字幕"按钮 | **区块门控**：没有识别到输入素材 | `ls output/` | 先下载或上传视频/音频 |
| 点了"停止"没立刻停 | `check_cancel()` 只在**接入点**生效（`core/step2_whisperX.py` 分段循环、`core/step4_2_translate_all.py` 的 `as_completed` 循环、`core/step3_2_splitbymeaning.py` 的提交/收集循环与 `split_sentence` 入口、`core/step5_splitforsub.py` 的 `process()` 入口、`core/translate_once.py:translate_lines` 入口），单次 LLM 请求内部无法打断。排队中的任务会被 `cancel()`，但**已开始执行**的那些必须跑完，数量上界是 `max_workers` | 看当前停在哪个步骤 | 正常现象。若等待过久，把 `max_workers`（dev 默认 `1000`）调小，停止会更快生效 |
| 任务一直停在"已提取术语，流程暂停中" | 这是 `pause_before_translate: true` 的**术语确认暂停点**（`runner.paused_for_review`） | 看提示文案 | 编辑 `output/log/terminology.json` 或 `custom_terms.xlsx` 后点「✅ 术语已确认，继续」 |
| 每个长句都"校验失败"并重试 3 次 | 提示词与消费端契约被改坏了一边：提示词必须要求 `split1/split2/assess/choice`，`valid_split` 必须校验 `choice ∈ {1,2}` | 跑 `tests/test_prompt_contract.py` | 两边成对修改，不要只改一边 |
| summary 的主题上下文恒为空 | JSON 键名不一致：dev 的提示词与 `core/step4_2_translate_all.py` 都用 **`topic`**（上游 3.x 用 `theme`） | `grep -n '"topic"\|"theme"' core/prompts_storage.py core/step4_2_translate_all.py` | 保持 `topic`。**不要**照上游改成 `theme` |
| `KeyError: Key 'xxx' not found in configuration` | 已存在的旧 `config.yaml` 不会自动补模板新增的键（`_read_config()` 只在文件**缺失**时从模板生成） | 对比 `config.example.yaml` | 用 `load_key_or()` 读可选键；或手工把缺失的段补进 `config.yaml`（如新增的 `youtube:`）；或删掉 `config.yaml` 让它重新生成（**会丢密钥**） |
| `python -m core.step2_whisperX` 抛 `UnicodeEncodeError: 'gbk'` | Windows 控制台默认 GBK，而模块打印 emoji | 直接看报错 | 已修：18 个带 `__main__` 的模块入口会调用 `easy_util.ensure_utf8_console()`。若在**自己新写的**脚本里遇到，同样先调它一次 |
| 装了依赖但启动仍报缺模块 | 安装**状态指纹**认为环境已一致而跳过了安装 | `python installer.py --check` | `python installer.py --force` 强制重装 |
| CPU 机器上装到了 CUDA 版 torch | 旧 `install.py` 的 bug（已修） | `python installer.py --check` 会打印 `torch 版本 / CUDA 可用` | 用 `python installer.py --force` 重装；`install_torch()` 会按 CPU/CUDA 选不同 wheel 源 |
| Linux 上烧录的中文字幕是方块 | 缺 CJK 字体（旧脚本装的是 `fonts-noto`，不含中日韩字形） | `fc-match "Noto Sans CJK SC"` | `python installer.py` 会装 `fonts-noto-cjk`（Debian）/`google-noto-sans-cjk-fonts`（RHEL）/`noto-fonts-cjk`（Arch） |
| macOS 上烧录的中文字幕是方块 | 原先只有 Linux 字体分支（已修） | 看 `core/step7_merge_sub_to_vid.py` 的 `Darwin` 分支 | 已改为 `Arial Unicode MS` |
| 启动时报端口 8501 被占用 | 上一次的实例还在跑 | `python launch.py --no-log` 会直接提示 | 关掉旧进程，或 `python launch.py --port 8502` |
| `output/` 下检测到多个视频文件 | `find_video_files()` **有意**取最新并告警（不是错误） | 看控制台告警 | 归档或移走多余文件；产物 `output_sub.mp4`/`output_dub.mp4` 会被自动排除 |
| 标题以 `output` 开头的源文件之前"消失"了 | 旧过滤条件 `not file.startswith("output/output")` 的 bug（已修） | `tests/test_media_input.py` | 已改为按 basename 排除明确的产物名 |

## 三、缓存相关的三个位置（最容易混）

| 位置 | 内容 | 键/失效条件 | 清理方式 |
| --- | --- | --- | --- |
| `.cache/asr/<key>/<part>.json` | 转录结果（`part` 为 `complete` 或 `f"{start:.2f}_{end:.2f}"`） | `cache_key()`：源媒体内容 + schema + whisperx/faster-whisper/demucs 版本 + `asr_engine`/model/language/demucs；火山再加 10 个参数。**不含**密钥、文件名、翻译设置 | 页面「清空转录缓存」/ `transcription_cache.clear_cache()` / 删目录 |
| `output/log/asr_results/volcano_asr_*.json` | 火山引擎自己的二级缓存 | 文件名 + 起止时间匹配 | 页面「清空 ASR 结果缓存」 |
| `output/gpt_log/<log_title>.json` | LLM 调用缓存 | prompt + model + log_title | `ask_gpt(..., use_cache=False)` 或 `bypass_cache=True`；或删文件 |

> ⚠️ 前两者**故意分开**：`.cache/asr` 在 `output/` 之外，所以"归档到历史记录"不会让它失效（这是有意的——不想因为清理产物就重复付费识别）。

## 四、怎么定位是哪一次改动引入的

```bash
git log --oneline dev..merge/upstream-3.0.4     # 每个提交对应一类改动，提交信息里写了对应上游 commit 与取舍理由
git show <sha>                                   # 提交信息里写了对应上游 commit 与取舍理由
git diff dev..merge/upstream-3.0.4 -- <文件>      # 只看某个文件的净变化
```

想临时退回 dev 的旧行为（不改分支）：

```bash
git revert <sha>          # 单个改动
git checkout dev -- <文件> # 只把某个文件退回 dev 版本
```

## 五、本次合并的验证边界（**未**验证的部分，排错时请留意）

- 合并时的开发机**没有可用的项目 Python 环境**（无 `videolingo` conda 环境，`json_repair`/`spacy`/`torch` 均未安装），因此**未做端到端跑通验证**。
- 已实测的部分：46 例单元测试；`ffmpeg` 真实抽取（raw.wav 的 ffprobe 三元组、raw.mp3 的 32kHz、12kHz 高频保留）；`find_media_file` 的 6 种输入场景；缓存键的引擎区分与 8 类畸形结果拒绝；`TaskRunner` 的暂停阻塞与停止提前退出；`fix_base_url`；`installer.py --check` 与 `launch.py --no-log` 的实际输出与退出码。
- **未**实测：Streamlit 页面的实际渲染（进度面板、暂停/停止按钮、字幕长度面板、模型搜索框）；火山 ASR 的真实请求链路（需凭据且产生费用）；macOS/Linux 上的烧录字体效果。
