## 二、环境与启动类

### `ModuleNotFoundError: No module named 'whisperx'` / `'streamlit'` / `'torch'`

| 项 | 内容 |
| --- | --- |
| 根因 | 没在 `videolingo` 环境里跑，或依赖没装 |
| 处置（先体检） | `conda activate videolingo` 后跑 **`python installer.py --check`**：它会逐项检查 Python 版本（3.10–3.11；3.12 因 torch 2.1.2 无 cp312 wheel 而被拒）、关键包能否 import、`torch`/`torchaudio` 是否同版本、`ffmpeg`/`ffprobe`、Linux CJK 字体、`config.yaml`；有错时**退出码为 1**，加 `--quiet` 只看问题 |
| 处置（补装） | `python install.py`（等价 `python installer.py --launch`）；确认 `python -c "import whisperx"` 能过 |
| 注意 | `OneKeyStart.bat` 硬编码 `%USERPROFILE%\anaconda3\envs\videolingo`（`OneKeyStart.bat:10`）；该目录不存在时它会直接打印「[错误] 未找到 conda 环境」并退出，不再用错误的 Python 静默跑下去 |

### 启动就失败 / 不知道缺什么：先跑 `python launch.py --no-log`

| 项 | 内容 |
| --- | --- |
| 用途 | `launch.py` 的 `preflight()`（`launch.py:45`）在启动 Streamlit **之前**检查三件事并把结论直接打在终端：① 关键包（`streamlit` / `json_repair` / `torch`）；② `ffmpeg` / `ffprobe`；③ 端口（默认 8501）是否已被占用（`launch.py:64-65`）。任一为错即**不启动**并返回 1，同时提示去跑 `python installer.py --check` |
| 命令 | `python launch.py --no-log`（只预检、不写日志）；`python launch.py`（启动并把运行日志写到 `logs/videolingo_<时间戳>.log`，同时回显到终端） |
| 注意 | `launch.py --port <n>` 可换端口；`--no-log` 时**不创建** `logs/` 目录 |

### `UnicodeEncodeError: 'gbk' codec can't encode character ...`（Windows）

| 项 | 内容 |
| --- | --- |
| 根因 | Windows 控制台默认 GBK，而代码打印 emoji/中文 |
| 处置 | `core/` 下 18 个带 `__main__` 的模块、`installer.py`、`launch.py` 都已在入口调用 `easy_util.ensure_utf8_console()`（`easy_util.py:7`），直接跑不再崩。若你**新写**的脚本打印 emoji，照 `core/step2_whisperX.py:540-548` 的写法补一次即可 |
| 备用 | 临时设 `$env:PYTHONIOENCODING = "utf-8"` 也可绕过 |

### `FileNotFoundError: [WinError 2] 系统找不到指定的文件` 且提到 `ffmpeg`

| 项 | 内容 |
| --- | --- |
| 根因 | PATH 里没有 ffmpeg |
| 处置 | 确认项目根有 `ffmpeg.exe`；用 `python -m streamlit run st.py` 启动（`st.py:13-15` 会把项目根注入 PATH）。若直接 `python core/step2_whisperX.py` 单步跑，需先把项目根加入 `PATH` |
| 验证 | `ffmpeg -version`；`ffprobe -version`（`installer.py:342` 要求两者都在） |

| 项 | 内容 |

### ⚠️ `API_KEY is missing` / `⚠️API_KEY is missing`

| 项 | 内容 |

### Streamlit 页面打开但点按钮无反应 / 一直转圈

| 项 | 内容 |
| --- | --- |
| 最可能原因 | **已修复，此条仅作历史参考**：旧实现是 `pause_before_translate: true` 触发 `st.py` 里的 `input()` 阻塞。现在改用后台执行器 `TaskRunner`，`pause_before_translate` 走的是 `TaskRunner.request_review_pause()`（`st_components/task_runner.py:81`），页面显示「✅ 术语已确认，继续」按钮，**不再读 stdin** |
| 若仍然卡住 | 看页面底部是否有「⏸️ 已暂停」提示条 —— 那是真的在等你在页面上点继续；点「⏹️ 停止」可退出（`st.py:139-165`） |
| 次可能原因 | 长任务仍在执行（正常现象）。转写 30 分钟视频可能要几分钟到几十分钟；此时进度条应显示「第 N/M 步：<步骤名>」（`st.py:123-126`） |

### 点了「开始处理字幕」后进度条一直不动 / 想中途放弃

| 项 | 内容 |
| --- | --- |
| 说明 | 任务在后台线程里顺序执行（`TaskRunner.start()`，`st_components/task_runner.py:99`），页面底部每秒刷新一次进度（`st.py:112` 的 `@st.fragment(run_every=1)`） |
| 暂停/停止 | 「⏸️ 暂停」会在下一个取消检查点阻塞；「⏹️ 停止」会在下一个检查点抛 `StopTask` 并退出。检查点只有 3 处：`core/step2_whisperX.py:500`（分段循环）、`core/step4_2_translate_all.py:125`（并发收集循环）、`core/translate_once.py:30`（每个 chunk 的翻译入口） |
| 停止后的状态 | 已完成的步骤产物保留在 `output/`，重新点开始会按幂等约定跳过；已开始的火山请求无法撤回 |

### 上传大视频失败

| 项 | 内容 |
| --- | --- |
| 根因 | Streamlit 默认上传上限 |
| 处置 | `.streamlit/config.toml` 已把 `maxUploadSize` 设为 `4096`(MB)。若还不够，改这个值并**重启** |

## 三、下载 / 源视频类

### `Number of videos found is not unique. Please check. Number of videos found: N`

| 项 | 内容 |
| --- | --- |
| 状态 | **该报错已不存在**。现在 0 个文件才抛 `FileNotFoundError`，多个文件只打印 `⚠️ ... 检测到 N 个视频文件，将使用最新的一个` 并继续（`core/step1_ytdlp.py:173-182`） |
| 若你看到的是这条老报错 | 说明跑的不是本分支的代码（或本地 `output/` 里有旧版行为），先确认 `python -c "import core.step1_ytdlp as m; print(m.__file__)"` |
| 仍然要留意的两点 | ① 候选过滤改成按**文件名**排除自制成品（`GENERATED_VIDEO_NAMES = {"output_sub.mp4", "output_dub.mp4"}`，`core/step1_ytdlp.py:150`）；`black_screen.mp4` 是**合法**源文件，不会被排除；② 「多个文件取最新」是按 mtime 排序，如果你刚放进去一个不相关的 mp4，它可能被选中 —— 建议保持 `output/` 只有一个源媒体 |
| 处置 | 用 UI 的「删除并重新选择」清空 `output/`；或 `Remove-Item output -Recurse -Force` |

### 下载视频失败 / yt-dlp 报错

| 项 | 内容 |
| --- | --- |
| 根因 | yt-dlp 每次下载前会 `pip install --upgrade yt-dlp`（`core/step1_ytdlp.py:93-97`），网络受限时可能反而失败（但有 try/except 兜底）；或视频需要登录 |
| 处置（登录/会员视频） | 用浏览器插件导出 Netscape 格式 `cookies.txt`，把路径填到 `config.yaml` 的 `youtube.cookies_path`（`core/step1_ytdlp.py:76-81`）；文件不存在时会打印告警并忽略 |
| 处置（代理） | `config.yaml` 的 `youtube.proxy`（`core/step1_ytdlp.py:87-91`）：缺省/`null` 交给 yt-dlp 自行发现，**空串表示显式禁用代理**，URL 表示强制使用 |
| 其他 | 手动 `pip install -U yt-dlp` 后重试；改用「上传视频」通道 |

### 上传音频后行为不符合预期

| 项 | 内容 |
| --- | --- |
| 现状 | 上传的音频**不再**被包成 `output/black_screen.mp4`，而是原样落盘 + 写一份 `output/input_manifest.json`（内容为 `{"path": ..., "type": "audio"}`，`core/step1_ytdlp.py:195`）；后续步骤按它区分音频/视频（`find_media_file()`，`core/step1_ytdlp.py:240`） |
| 症状：提示「该文件已导入过」 | 这是**上传幂等保护**（`st_components/download_video_section.py:75-78`）。想重新导入请先点「删除并重新选择」，或换一个文件 |
| 症状：界面把音频当成了视频/没显示播放器 | 检查 `output/input_manifest.json` 是否存在且 `type` 正确；清单缺失或指向的文件已不存在时，`read_input_manifest()` 返回 `None`，会回退到"按扩展名找视频→再找音频"（`core/step1_ytdlp.py:203-219`、`:240-252`） |
| 症状：切换素材后处理的是上一个文件 | 清单里记的是**绝对/相对路径**，换素材时 UI 会重建 `output/`（`download_video_section.py:81-83`）。手工往里拷文件时请一并更新或删除该清单 |
| 预期结果 | 纯音频输入只产出字幕文件，不做压制（`core/step7_merge_sub_to_vid.py:65-68`） |

### 转写结果为空 / `cleaned_chunks.xlsx` 只有表头

### `Please specify the transcription language as zh and try again!`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step2_whisperX.py:240-241` |
| 根因 | 检测到语言是 `zh`，但 `whisper.language` 配的不是 `zh`。中文必须显式指定，才会走 Belle 标点模型（`load_whisper_model_name()`，`core/step2_whisperX.py:103`） |

### 转写报 `Audio segment too short for processing`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step2_whisperX.py:206-207` |
| 根因 | 切片后的音频不足 100 采样点（~6ms）。通常是源音频本身几乎静音或切片边界异常 |

### 转写极慢（CPU）

| --- | --- |
| 现象 | 启动日志显示 `🚀 Starting WhisperX using device: cpu` |

### 显存不足 / `CUDA out of memory`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step2_whisperX.py:151-159` 会按显存选 `batch_size`（>8GB 用 16，否则 2），但仍可能不够 |
| 处置 | 临时改小该处的 `batch_size`；或先关掉 Demucs（`demucs: false`）以释放显存 |

### 模型下载慢 / 卡在 HuggingFace / 想强制走国内镜像

| 项 | 内容 |
| --- | --- |
| 现状 | 首次转录时 `check_hf_mirror()`（`core/step2_whisperX.py:43`）会 ping `huggingface.co` 与 `hf-mirror.com` 取更快的一个，写进 `os.environ['HF_ENDPOINT']`（`core/step2_whisperX.py:146`）。探测结果**同进程只算一次**（`_HF_ENDPOINT_CACHE`，`core/step2_whisperX.py:41`），所以终端里只会看到一次 `🔍 Checking HuggingFace mirrors...` |
| 想强制指定 | 自己设 `HF_ENDPOINT`（如 `$env:HF_ENDPOINT = "https://hf-mirror.com"`）：非空时直接尊重该值、**完全不探测**（`core/step2_whisperX.py:52-56`） |
| 症状：换了镜像但没生效 | 该缓存是**进程级**的：改环境变量后必须重启 Streamlit 进程 |
| 症状：本地模型目录下载到一半 | `resolve_whisper_model()`（`core/step2_whisperX.py:110`）要求目录里同时有非空的 `config.json` / `model.bin` / `tokenizer.json`（`_REQUIRED_MODEL_FILES`，`core/step2_whisperX.py:90`），不完整会打印 `⚠️ 本地模型目录不完整...` 并重新联网获取 |

| 处置 | 看 `output/gpt_log/translate_expressiveness.json` 里该次的返回；通常是模型把两行合并/拆分了。换更强的模型（`llm_support_json` 白名单内的模型更稳），或把 `split_chunks_by_chars` 的块调小 |

### `Translation matching failed (chunk N)`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step4_2_translate_all.py:158-160` |
| 根因 | 并发返回的结果与原始 chunk 做 `SequenceMatcher` 匹配时相似度 < 0.9。多发生在**大段重复文本**（口头禅、歌词）上 |
| 处置 | 降低 `max_workers`（改为 1 可完全避免错配）；或减小 chunk 尺寸 |
| 深入 | P3-5 |

## 六、字幕 / 时间轴类（step5~step7）

### `❎ 未找到与句子匹配的内容。`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step6_generate_final_timeline.py:169` |
| 根因 | 词级长串与句子文本**逐字符**精确匹配失败。常见原因：① 下游忘了把 `cleaned_chunks.xlsx` 的 `text` 去掉外层双引号（应 `.str.strip('"').str.strip()`）；② 句子文件被人为编辑过；③ `step3` 的切分改变了字符（不只是空格/换行） |
| 处置 | 复现诊断（见下节「对齐诊断脚本」）；确认 `cleaned_chunks.xlsx` 的 text 是否带引号；一致后删 `output/*.srt` 重跑 step6 |
| 深入 | P1-3 |

### 字幕时间轴错位 / 字幕提前或延后

| 项 | 内容 |
| --- | --- |
| 根因 | ① `step5` 又切分了句子，但 `step6` 用切分后的文本重新匹配——正常会成功，若失败会报错；② 手工改过 `translation_results_for_subtitles.xlsx` 的 `Source` 列 |
| 处置 | 不要改 `Source` 列（它是匹配键），只改 `Translation`；删 `output/*.srt` 重跑 step6 |

### 字幕出现多行 / 单行过长

| 项 | 内容 |
| --- | --- |
| 根因 | `subtitle.max_length`（默认 75）与 `subtitle.target_multiplier`（默认 1.2）；`step5` 最多重试 3 轮切分，仍有超长会保留原样 |
| 处置 | 调小 `max_length` 会让切分更碎（增加 LLM 调用）；中文场景注意 `calc_len()` 的加权规则（中日字符 1.75、韩 1.5） |

### 压制报 `字幕文件不存在，请先运行 step6 生成字幕。`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step7_merge_sub_to_vid.py:90-95` |
| 根因 | 缺 `output/src.srt` 或 `output/trans.srt`（step6 没跑或产物被删）。抛的是 `FileNotFoundError`（**不是** `exit(1)`，见 P3-35） |
| 处置 | 先跑 step6 |

### 成片只有 1 秒黑屏

| 项 | 内容 |
| --- | --- |
| 状态 | **该行为已取消**。现在 `resolution: '0x0'` 时：输入是**真实视频** → **完全不生成** `output/output_sub.mp4`（还会清掉上一次遗留的成片）；输入是纯音频（`input_manifest` 记为 `audio`，或旧的 `black_screen.mp4`）→ 原样复制成 `output/output_sub.mp4`，保住音频与时长（`core/step7_merge_sub_to_vid.py:75-88`） |
| 若你看到只有 1 秒黑屏 | 说明跑的是旧代码 |
| 想要成片 | 把 `resolution` 设为 `640x360` 或 `1920x1080`（等价于侧边栏的「Burn-in Subtitles」开关打开）后重跑 step7 |

## 八、状态与缓存类（最高频的"玄学"）

### 改了代码/参数，结果完全没变

按顺序检查五件事：

| 检查 | 命令 | 说明 |
| --- | --- | --- |
| ① 该步是否被幂等跳过 | 看控制台是否有 `already exists, skip` / `already exists, skipping` 字样 | 每个 step 都有跳过逻辑 |
| ② LLM 缓存是否命中 | `Remove-Item output\gpt_log\*.json` | 见「LLM/翻译类」 |
| ③ 火山 ASR 二级缓存是否命中 | UI 侧边栏底部的「🔧 火山 ASR 结果缓存」折叠区点「清空 ASR 结果缓存」；等价于 `Remove-Item output\log\asr_results\*.json` | 目录 `output/log/asr_results/`（`st.py:259-276`，属于 `cache_maintenance_section()`）。**改了火山参数（模型版本/标点/DDC/ITN…）必须清这里**，否则会直接复用旧 JSON，表现为"改了参数没效果" |
| ④ 转录缓存是否命中 | UI 侧边栏底部的「♻️ 转录缓存」折叠区点「清空转录缓存」；等价于 `Remove-Item -Recurse -Force .cache\asr` | 目录 `.cache/asr/<key>/<part>.json`（`core/all_whisper_methods/transcription_cache.py:29`）。命中时控制台会打印 `♻️ 命中转录缓存：跳过音频分离与识别` 或 `♻️ 复用缓存分段 <start>_<end>`（`core/step2_whisperX.py:459`、`:513`）。⚠️ 它**不在 `output/` 下**，所以「删除并重新选择」/ 归档 output 都不会清掉它（`.gitignore:159` 也是刻意这么排的） |
| ⑤ 下游产物是否还是旧的 | 按 [`../00-overview/02-数据流与中间产物.md`](../00-overview/02-数据流与中间产物.md) 的"想重跑删什么"表删文件 | — |

> 📌 转写缓存的身份是「源媒体内容 + ASR 设置 + 包版本」（`transcription_cache.py:45` 的 `cache_key()`）：
> **换模型 / 换引擎（whisper↔volcano）/ 改识别语言 / 开关 demucs / 改火山那 10 个参数会自动失效**，
> 而改密钥、改文件名、改翻译设置**不会**失效（那是刻意的）。

### 对齐诊断：为什么匹配失败

import pandas as pd, re
df = pd.read_excel('output/log/cleaned_chunks.xlsx')

def clean(t): return re.sub(r'[^\w\s]', '', re.sub(r'\s+', ' ', t)).strip()
words = ''.join(clean(str(w).strip('"').lower()) for w in df['text'])
sents = [l.strip() for l in open('output/log/translation_results_for_subtitles.xlsx'.replace('.xlsx','') , encoding='utf-8')] if False else None
tr = pd.read_excel('output/log/translation_results_for_subtitles.xlsx')
pos = 0
for i, s in tr['Source'].items():
    cs = clean(str(s).lower()).replace(' ', '')
    idx = words.find(cs, pos)

txt = open('output/trans.srt', encoding='utf-8').read()
blocks = [b for b in txt.strip().split('\n\n') if b.strip()]
nums = [int(b.split('\n')[0]) for b in blocks]

times = [tuple(sec(x) for x in b.split('\n')[1].split(' --> ')) for b in blocks]
