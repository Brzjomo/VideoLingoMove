## 二、环境与启动类

### `ModuleNotFoundError: No module named 'whisperx'` / `'streamlit'` / `'torch'`

| 项 | 内容 |
| --- | --- |
| 根因 | 没在 `videolingo` 环境里跑，或依赖没装 |
| 处置 | `conda activate videolingo`；`python install.py`；确认 `python -c "import whisperx"` 能过 |
| 注意 | 所有 `.bat` 都硬编码 `%USERPROFILE%\anaconda3\Scripts\activate.bat videolingo`，环境名不一致会静默用错解释器 |

### `FileNotFoundError: [WinError 2] 系统找不到指定的文件` 且提到 `ffmpeg`

| 项 | 内容 |
| --- | --- |
| 根因 | PATH 里没有 ffmpeg |
| 处置 | 确认项目根有 `ffmpeg.exe`；用 `python -m streamlit run st.py` 启动（`st.py:9` 会把项目根注入 PATH）。若直接 `python core/step2_whisperX.py` 单步跑，需先 `$env:PATH += ";E:\VideoLingo\VideoLingoMove"` |
| 验证 | `ffmpeg -version` |

### `KeyError: Key 'xxx' not found in configuration`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/config_utils.py:25` |
| 根因 | `config.yaml` 缺键，或键路径写错（`load_key('whisper.language')` 用的是点号路径） |
| 处置 | 对照 [`../04-interfaces/01-配置文件与参数.md`](../04-interfaces/01-配置文件与参数.md) 的键表补全；注意 `load_key` **每次重新读文件**，改完立即生效 |

### ⚠️ `API_KEY is missing` / `⚠️API_KEY is missing`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/ask_gpt.py:63-64` |
| 根因 | `config.yaml: api.key` 为空。注意 `ask_gpt` **只读 `api` 这一组**，`deepseek_api` / `qwen_api` 等预设不会自动生效 |
| 处置 | 在侧边栏点一下对应的 API 预设（会把预设 `assign_key` 到 `api`），或直接填 `api.key` |

### Streamlit 页面打开但点按钮无反应 / 一直转圈

| 项 | 内容 |
| --- | --- |
| 最可能原因 | 后端在等待 stdin —— 即 `pause_before_translate: true` 触发了 `st.py:109` 的 `input()` |
| 处置 | 把 `pause_before_translate` 改成 `false`，重启；或在单步模式下跑 |
| 次可能原因 | 长任务同步阻塞（正常现象）。转写 30 分钟视频可能要几分钟到几十分钟 |

### 上传大视频失败

| 项 | 内容 |
| --- | --- |
| 根因 | Streamlit 默认上传上限 |
| 处置 | `.streamlit/config.toml` 已把 `maxUploadSize` 设为 `4096`(MB)。若还不够，改这个值并**重启** |

## 三、下载 / 源视频类

### `Number of videos found is not unique. Please check. Number of videos found: N`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step1_ytdlp.py:88-89` |
| 根因 | `output/` 下符合 `allowed_video_formats` 的文件不是恰好 1 个 |
| 常见触发 | ① 上传**音频**会生成 `output/black_screen.mp4`；② 上次的成片 `output_sub.mp4` 未被排除？——不会，代码排除了以 `output/output` 开头者；③ 用户手工放了多个视频 |
| 处置 | 只留一个源视频；用 UI 的「删除并重新选择」清空 `output/`；或 `Remove-Item output -Recurse -Force` |

### 下载视频失败 / yt-dlp 报错

| 项 | 内容 |
| --- | --- |
| 根因 | yt-dlp 每次下载前会 `pip install --upgrade yt-dlp`（`core/step1_ytdlp.py:34-40`），网络受限时可能反而失败（但有 try/except 兜底）；或视频需要登录 |
| 处置 | 手动 `pip install -U yt-dlp` 后重试；改用「上传视频」通道 |

### 上传音频后卡住

| 项 | 内容 |
| --- | --- |
| 位置 | `st_components/download_video_section.py:67-76` |
| 根因 | 音频会被转成 `output/black_screen.mp4`（640×360 黑底），转换后**原音频被删除**。若 ffmpeg 失败，`output/` 里会留下无视频状态 |
| 处置 | 查 ffmpeg 是否可用；重新上传 |

| 项 | 内容 |
| --- | --- |

### 火山引擎 ASR 相关报错

## 五、LLM / 翻译类

### `Request error ... Retrying (1/3)...` 然后 `Still failed after 3 attempts`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/ask_gpt.py:113-120` |
| 根因 | 网络不可达 / base_url 或 key 错误 / 模型名不存在 |
| 处置 | 注意 base_url 拼接规则（`core/ask_gpt.py:68`）：若 URL 里**任何位置**出现 `v1` 就原样使用，否则追加 `/v1`。所以 `https://api.deepseek.com` → `https://api.deepseek.com/v1`（正确）；但 `http://localhost:11434/v1` 已含 `v1`，保持不变（正确）；**而 `https://api.siliconflow.cn` → `https://api.siliconflow.cn/v1`**。若你的服务路径不是 `/v1`，需在 config 里写完整路径 |

### 控制台刷 `❎ json_repair parsing failed. Retrying: '''...'''`，但模型返回的明明是合法 JSON

| 项 | 内容 |
| --- | --- |
| 根因 | 已知缺陷 P0-2：`valid_def` 业务校验失败与 JSON 解析失败共用了同一个 `except`，错误信息被误写 |
| 处置 | 去 `output/gpt_log/error.json` 看**真实的** `response`，按业务规则判断缺了什么字段（例如 `Missing required key: split`）。若提示词改了导致输出格式变化，修正提示词 |
| 深入 | [`04-已知问题与技术债.md`](04-已知问题与技术债.md) 的 P0-2 |

### 🚨 改了提示词 / 换了模型，但输出完全没变

| 项 | 内容 |
| --- | --- |
| 根因 | **LLM 结果缓存**：`output/gpt_log/<log_title>.json` 以 prompt 全文为键，命中即直接返回（`core/ask_gpt.py:34-45`），且**不看模型名** |
| 处置 | `Remove-Item output\gpt_log\*.json` 后重跑；同时删掉下游产物（如 `output/log/translation_results.xlsx`、`output/log/sentence_splitbymeaning.txt`）以触发重算 |
| 深入 | [`../03-subsystems/01-LLM调用与提示词.md`](../03-subsystems/01-LLM调用与提示词.md)、P1-1 |

### `Translation of block N failed, Length Mismatch`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/translate_once.py:86-88` |
| 根因 | LLM 输出的行数与输入行数不一致（`retry_translation` 已重试 3 次仍不一致） |
| 处置 | 看 `output/gpt_log/translate_expressiveness.json` 里该次的返回；通常是模型把两行合并/拆分了。换更强的模型（`llm_support_json` 白名单内的模型更稳），或把 `split_chunks_by_chars` 的块调小 |

### `Translation matching failed (chunk N)`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step4_2_translate_all.py:135` |
| 根因 | 并发返回的结果与原始 chunk 做 `SequenceMatcher` 匹配时相似度 < 0.9。多发生在**大段重复文本**（口头禅、歌词）上 |
| 处置 | 降低 `max_workers`（改为 1 可完全避免错配）；或减小 chunk 尺寸 |
| 深入 | P3-5 |

## 六、字幕 / 时间轴类（step5~step7）

### `❎ 未找到与句子匹配的内容。`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step6_generate_final_timeline.py:110` |
| 根因 | 词级长串与句子文本**逐字符**精确匹配失败。常见原因：① 下游忘了把 `cleaned_chunks.xlsx` 的 `text` 去掉外层双引号（应 `.str.strip('"').str.strip()`）；② 句子文件被人为编辑过；③ `step3` 的切分改变了字符（不只是空格/换行） |
| 处置 | 复现诊断（见下节「对齐诊断脚本」）；确认 `cleaned_chunks.xlsx` 的 text 是否带引号；一致后删 `output/*.srt` 重跑 step6 |
| 深入 | P1-3 |

### 字幕时间轴错位 / 字幕提前或延后

| 项 | 内容 |
| --- | --- |
| 根因 | ① `step5` 又切分了句子，但 `step6` 用切分后的文本重新匹配——正常会成功，若失败会报错；② 手工改过 `translation_results_for_subtitles.xlsx` 的 `Source` 列 |
| 处置 | 不要改 `Source` 列（它是匹配键），只改 `Translation`；删 `output/*.srt` 重跑 step6 |

### 字幕出现多行 / 单行过长

| 项 | 内容 |
| --- | --- |
| 根因 | `subtitle.max_length`（默认 75）与 `subtitle.target_multiplier`（默认 1.2）；`step5` 最多重试 3 轮切分，仍有超长会保留原样 |
| 处置 | 调小 `max_length` 会让切分更碎（增加 LLM 调用）；中文场景注意 `calc_len()` 的加权规则（中日字符 1.75、韩 1.5） |

### 压制报 `Subtitle files not found in the 'output' directory.`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step7_merge_sub_to_vid.py:61-63` |
| 根因 | 缺 `output/src.srt` 或 `output/trans.srt`（step6 没跑或产物被删） |
| 处置 | 先跑 step6 |

### 成片只有 1 秒黑屏

| 项 | 内容 |
| --- | --- |
| 根因 | `resolution: '0x0'`（占位模式，见 P2-9） |
| 处置 | 设为 `640x360` 或 `1920x1080` 后重跑 step7/step12 |

| 项 | 内容 |
| --- | --- |
| 根因 | `output/dub.mp3` 为空或 `segs/` 为空。`step11` 对缺失文件只打印 `⚠️ Warning: File ... does not exist, skipping...` 而**不报错** |
| 处置 | 检查 `output/audio/segs/` 是否有 `*.wav`；若有缺失，重跑 step10 |

## 八、状态与缓存类（最高频的"玄学"）

### 改了代码/参数，结果完全没变

按顺序检查三件事：

| 检查 | 命令 | 说明 |
| --- | --- | --- |
| ① 该步是否被幂等跳过 | 看控制台是否有 `already exists, skip` / `already exists, skipping` 字样 | 每个 step 都有跳过逻辑 |
| ② LLM 缓存是否命中 | `Remove-Item output\gpt_log\*.json` | 见「LLM/翻译类」 |
| ③ 下游产物是否还是旧的 | 按 [`../00-overview/02-数据流与中间产物.md`](../00-overview/02-数据流与中间产物.md) 的"想重跑删什么"表删文件 | — |

```powershell
# 方式一：UI 上点「删除并重新选择」（会 rmtree output）
# 方式二：手工
Remove-Item -Recurse -Force output
```

## 九、诊断脚本（可直接粘贴运行）

### 对齐诊断：为什么匹配失败

```python
import pandas as pd, re
df = pd.read_excel('output/log/cleaned_chunks.xlsx')
print('cleaned_chunks 前 5 行:'); print(df.head())
print('text 是否带引号:', df['text'].iloc[0][:1] == '"')

# 复现 step6 的清洗与拼接
def clean(t): return re.sub(r'[^\w\s]', '', re.sub(r'\s+', ' ', t)).strip()
```
