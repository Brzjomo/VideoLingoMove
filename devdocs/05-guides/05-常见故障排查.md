## 二、环境与启动类

### `ModuleNotFoundError: No module named 'whisperx'` / `'streamlit'` / `'torch'`

| 项 | 内容 |
| --- | --- |
| 根因 | 没在**项目内 `.venv`** 里跑，或依赖没装 |
| 处置（先体检） | 用项目环境的解释器跑 **`python installer.py --check`**（即 `.venv\Scripts\python.exe installer.py --check`）：它会逐项检查 Python 版本（**3.10–3.13，推荐 3.11**）、关键包能否 import、`torch`/`torchaudio`/`torchvision` 是否同版本同源、`ffmpeg` 大版本是否在 4–7、Linux CJK 字体、`config.yaml`；有错时**退出码为 1**，加 `--quiet` 只看问题 |
| 处置（补装） | `Install.bat`（一键，可重复运行）或 `python setup_env.py --python 3.11` 后 `python installer.py`；确认 `python -c "import whisperx"` 能过 |
| 注意 | 三个启动脚本（`OneKeyStart.bat` / `batch\StartBatch.bat` / `AudioExtract\Start.bat`）都用同一套探测顺序：**项目内 `.venv` → conda 环境 `videolingo` → PATH 上的 python**。都不满足时 `OneKeyStart.bat` 会打印 `[ERROR] No usable Python 3.10-3.13 found.` 并提示你去跑 `Install.bat`，不会用错误的解释器静默跑下去 |
| ⚠️ 别用旧 conda 环境 | `videolingo` conda 环境是**升级前的老栈**（torch 2.1.2+cu118 / streamlit 1.38 / spacy 3.7），只能跑不依赖新栈的单元测试；跑本分支的 `st.py` 会因 `width="stretch"` 等新 API 报错 |

### 启动就失败 / 不知道缺什么：先跑 `python launch.py --no-log`

| 项 | 内容 |
| --- | --- |
| 用途 | `launch.py` 的 `preflight`（`launch.py`）在启动 Streamlit **之前**检查三件事并把结论直接打在终端：① 关键包（`streamlit` / `json_repair` / `torch`）；② `ffmpeg` / `ffprobe`；③ 端口（默认 8501）是否已被占用（`launch.py`）。任一为错即**不启动**并返回 1，同时提示去跑 `python installer.py --check` |
| 命令 | `python launch.py --no-log`（只预检、不写日志）；`python launch.py`（启动并把运行日志写到 `logs/videolingo_<时间戳>.log`，同时回显到终端） |
| 注意 | `launch.py --port <n>` 可换端口；`--no-log` 时**不创建** `logs/` 目录 |

### `UnicodeEncodeError: 'gbk' codec can't encode character ...`（Windows）

| 项 | 内容 |
| --- | --- |
| 根因 | Windows 控制台默认 GBK，而代码打印 emoji/中文 |
| 处置 | `core/` 下 18 个带 `__main__` 的模块、`installer.py`、`launch.py` 都已在入口调用 `easy_util.ensure_utf8_console`（`easy_util.py`），直接跑不再崩。若你**新写**的脚本打印 emoji，照 `core/step2_whisperX.py` 的写法补一次即可 |
| 备用 | 临时设 `$env:PYTHONIOENCODING = "utf-8"` 也可绕过 |

### `FileNotFoundError: [WinError 2] 系统找不到指定的文件` 且提到 `ffmpeg`

| 项 | 内容 |
| --- | --- |
| 根因 | PATH 里没有 ffmpeg，或者那份是**静态**构建（`torchcodec` 用不了） |
| 处置 | 首选让 `Install.bat` 把 FFmpeg 放到项目内 `ffmpeg\`（运行期由 `runtime_libraries.py` 自动接入 DLL 搜索路径与 PATH，不需要你改环境变量、也不用重启终端）。系统里已有合规版本时安装脚本会跳过下载 |
| 验证 | `ffmpeg -version`（大版本需在 **4–7**）；`ffprobe -version`（`installer.py` 的 `health_check` 要求两者都在） |

### `KeyError: Key 'xxx' not found in configuration`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/config_utils.py`（`load_key` 定义在） |
| 根因 | `config.yaml` 缺键，或键路径写错（`load_key('whisper.language')` 用的是点号路径） |
| 处置 | 对照 [`../04-interfaces/01-配置文件与参数.md`](../04-interfaces/01-配置文件与参数.md) 的键表补全；注意 `load_key` **每次重新读文件**，改完立即生效 |

### ⚠️ `API_KEY is missing` / `⚠️API_KEY is missing`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/ask_gpt.py`（`raise ValueError("API_KEY is missing")`） |
| 根因 | `config.yaml: api.key` 为空。注意 `ask_gpt` **只读 `api` 这一组**，`deepseek_api` / `qwen_api` 等预设不会自动生效 |
| 处置 | 在侧边栏点一下对应的 API 预设（会把预设 `assign_key` 到 `api`），或直接填 `api.key`；也可以用 `VIDEOLINGO_API_KEY` 环境变量覆盖（`core/config_utils.py`） |

### Streamlit 页面打开但点按钮无反应 / 一直转圈

| 项 | 内容 |
| --- | --- |
| 最可能原因 | **已修复，此条仅作历史参考**：旧实现是 `pause_before_translate: true` 触发 `st.py` 里的 `input` 阻塞。现在改用后台执行器 `TaskRunner`，`pause_before_translate` 走的是 `TaskRunner.request_review_pause`（`st_components/task_runner.py`），页面显示「✅ 术语已确认，继续」按钮，**不再读 stdin** |
| 若仍然卡住 | 看页面底部是否有「⏸️ 已暂停」提示条 —— 那是真的在等你在页面上点继续；点「⏹️ 停止」可退出（`st.py`） |
| 次可能原因 | 长任务仍在执行（正常现象）。转写 30 分钟视频可能要几分钟到几十分钟；此时进度条应显示「第 N/M 步：<步骤名>」（`st.py`） |

### 点了「开始处理字幕」后进度条一直不动 / 想中途放弃

| 项 | 内容 |
| --- | --- |
| 说明 | 任务在后台线程里顺序执行（`TaskRunner.start`，`st_components/task_runner.py`），页面底部每秒刷新一次进度（`st.py` 的 `@st.fragment(run_every=1)`） |
| 暂停/停止 | 「⏸️ 暂停」会在下一个取消检查点阻塞；「⏹️ 停止」会在下一个检查点抛 `StopTask` 并退出。检查点有 7 处：`core/step2_whisperX.py`（分段循环）、`core/step4_2_translate_all.py`（并发收集循环）、`core/translate_once.py`（每个 chunk 的翻译入口） |
| 停止后的状态 | 已完成的步骤产物保留在 `output/`，重新点开始会按幂等约定跳过；已开始的火山请求无法撤回 |

### 上传大视频失败

| 项 | 内容 |
| --- | --- |
| 根因 | Streamlit 默认上传上限 |
| 处置 | `.streamlit/config.toml` 已把 `maxUploadSize` 设为 `4096`(MB)。若还不够，改这个值并**重启** |

## 三、下载 / 源视频类

### `Number of videos found is not unique. Please check. Number of videos found: N`

| 项 | 内容 |
| --- | --- |
| 状态 | **该报错已不存在**。现在 0 个文件才抛 `FileNotFoundError`，多个文件只打印 `⚠️ ... 检测到 N 个视频文件，将使用最新的一个` 并继续（`core/step1_ytdlp.py`） |
| 若你看到的是这条老报错 | 说明跑的不是本分支的代码（或本地 `output/` 里有旧版行为），先确认 `python -c "import core.step1_ytdlp as m; print(m.__file__)"` |
| 仍然要留意的两点 | ① 候选过滤改成按**文件名**排除自制成品（`GENERATED_VIDEO_NAMES = {"output_sub.mp4", "output_dub.mp4"}`，`core/step1_ytdlp.py`）；`black_screen.mp4` 是**合法**源文件，不会被排除；② 「多个文件取最新」是按 mtime 排序，如果你刚放进去一个不相关的 mp4，它可能被选中 —— 建议保持 `output/` 只有一个源媒体 |
| 处置 | 用 UI 的「删除并重新选择」清空 `output/`；或 `Remove-Item output -Recurse -Force` |

### 下载视频失败 / yt-dlp 报错

| 项 | 内容 |
| --- | --- |
| 根因 | yt-dlp 每次下载前会 `pip install --upgrade yt-dlp`（`core/step1_ytdlp.py`），网络受限时可能反而失败（但有 try/except 兜底）；或视频需要登录 |
| 处置（登录/会员视频） | 用浏览器插件导出 Netscape 格式 `cookies.txt`，把路径填到 `config.yaml` 的 `youtube.cookies_path`（`core/step1_ytdlp.py`）；文件不存在时会打印告警并忽略 |
| 处置（代理） | `config.yaml` 的 `youtube.proxy`（`core/step1_ytdlp.py`）：缺省/`null` 交给 yt-dlp 自行发现，**空串表示显式禁用代理**，URL 表示强制使用 |
| 其他 | 手动 `pip install -U yt-dlp` 后重试；改用「上传视频」通道 |

### 上传音频后行为不符合预期

| 项 | 内容 |
| --- | --- |
| 现状 | 上传的音频**不再**被包成 `output/black_screen.mp4`，而是原样落盘 + 写一份 `output/input_manifest.json`（内容为 `{"path": ..., "type": "audio"}`，`core/step1_ytdlp.py`）；后续步骤按它区分音频/视频（`find_media_file`，`core/step1_ytdlp.py`） |
| 症状：提示「该文件已导入过」 | 这是**上传幂等保护**（`st_components/download_video_section.py`）。想重新导入请先点「删除并重新选择」，或换一个文件 |
| 症状：界面把音频当成了视频/没显示播放器 | 检查 `output/input_manifest.json` 是否存在且 `type` 正确；清单缺失或指向的文件已不存在时，`read_input_manifest` 返回 `None`，会回退到"按扩展名找视频→再找音频"（`core/step1_ytdlp.py`） |
| 症状：切换素材后处理的是上一个文件 | 清单里记的是**绝对/相对路径**，换素材时 UI 会重建 `output/`（`download_video_section.py`）。手工往里拷文件时请一并更新或删除该清单 |
| 预期结果 | 纯音频输入只产出字幕文件，不做压制（`core/step7_merge_sub_to_vid.py`） |

## 四、转写类（step2）

### 转写结果为空 / `cleaned_chunks.xlsx` 只有表头

| 项 | 内容 |
| --- | --- |
| 根因 | 多为音频过短或切片异常；`whisperX_utils.split_audio` 有 0.5s 最小段长约束（`core/all_whisper_methods/whisperX_utils.py`） |
| 处置 | 检查 `output/audio/for_whisper.mp3` 是否正常（能否播放、时长是否正确） |
| 先排除缓存 | 若控制台打印过 `♻️ 命中转录缓存：跳过音频分离与识别`，说明结果直接来自 `.cache/asr`，源音频的问题不会暴露。清缓存（见「八」）后重跑再看 |

### `Please specify the transcription language as zh and try again!`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step2_whisperX.py` |
| 根因 | 检测到语言是 `zh`，但 `whisper.language` 配的不是 `zh`。中文必须显式指定，才会走 Belle 标点模型（`load_whisper_model_name`，`core/step2_whisperX.py`） |
| 处置 | 在侧边栏把「Recog Lang」切成中文（会同步写 `whisper.language` 与 `whisper.detected_language`，见 `core/config_utils.py`），或手改 `config.yaml: whisper.language: 'zh'` |

### 转写报 `Audio segment too short for processing`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step2_whisperX.py` |
| 根因 | 切片后的音频不足 100 采样点（~6ms）。通常是源音频本身几乎静音或切片边界异常 |
| 处置 | 检查源视频音轨；若整段无语音，本工具无意义 |

### 转写极慢（CPU）

| 项 | 内容 |
| --- | --- |
| 现象 | 启动日志显示 `🚀 Starting WhisperX using device: cpu` |
| 根因 | `torch.cuda.is_available` 为 False（没装 CUDA 版 torch / 驱动不匹配） |
| 处置 | `python -c "import torch; print(torch.__version__, torch.cuda.is_available)"`；新栈应为 `2.8.0+cu126`/`+cu128`/`+cu129`（按显卡算力）且 `True`。重装见 [`../06-batch-and-tools/02-安装脚本与依赖.md`](../06-batch-and-tools/02-安装脚本与依赖.md) |

### 显存不足 / `CUDA out of memory`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step2_whisperX.py` 会按显存选 `batch_size`（>8GB 用 16，否则 2），但仍可能不够 |
| 处置 | 临时改小该处的 `batch_size`；或先关掉 Demucs（`demucs: false`）以释放显存 |

### 模型下载慢 / 卡在 HuggingFace / 想强制走国内镜像

| 项 | 内容 |
| --- | --- |
| 现状 | 首次转录时 `check_hf_mirror`（`core/step2_whisperX.py`）会 ping `huggingface.co` 与 `hf-mirror.com` 取更快的一个，写进 `os.environ['HF_ENDPOINT']`（`core/step2_whisperX.py`）。探测结果**同进程只算一次**（`_HF_ENDPOINT_CACHE`，`core/step2_whisperX.py`），所以终端里只会看到一次 `🔍 Checking HuggingFace mirrors...` |
| 想强制指定 | 自己设 `HF_ENDPOINT`（如 `$env:HF_ENDPOINT = "https://hf-mirror.com"`）：非空时直接尊重该值、**完全不探测**（`core/step2_whisperX.py`）。⚠️ 但**必须在启动进程之前**设 —— `huggingface_hub` 在 import 时只读一次，运行期再改无效；因此 `check_hf_mirror()` 那句运行期赋值实际**不生效**（实测见下面「对齐模型」一节） |
| 症状：换了镜像但没生效 | 该缓存是**进程级**的：改环境变量后必须重启 Streamlit 进程 |
| 症状：本地模型目录下载到一半 | `resolve_whisper_model`（`core/step2_whisperX.py`）要求目录里同时有非空的 `config.json` / `model.bin` / `tokenizer.json`（`_REQUIRED_MODEL_FILES`，`core/step2_whisperX.py`），不完整会打印 `⚠️ 本地模型目录不完整...` 并重新联网获取 |

### `Can't load feature extractor for '…'` / `The chosen align_model "…" could not be found in huggingface`（其实是**网络**问题）

2026-09-20 实测：日语视频跑到转录末尾的对齐（alignment）一步失败，控制台在
`Progress: 100.00%...` 之后出现：

```text
Can't load feature extractor for 'jonatasgrosman/wav2vec2-large-xlsr-53-japanese'.
… make sure you don't have a local directory with the same name. Otherwise, make sure
'jonatasgrosman/wav2vec2-large-xlsr-53-japanese' is the correct path to a directory
containing a preprocessor_config.json file
Error loading model from huggingface, check https://huggingface.co/models for finetuned wav2vec2.0 models
ValueError: The chosen align_model "jonatasgrosman/wav2vec2-large-xlsr-53-japanese"
could not be found in huggingface (https://huggingface.co/models) or torchaudio (…)
```

| 项 | 内容 |
| --- | --- |
| ⚠️ 别被误导 | 这两句都在暗示"模型名/路径写错了"，**真因是网络**：该仓库不在本地缓存、又拿不到文件元数据时，`transformers/feature_extraction_utils.py` 把 `cached_file()` 返回 `None` 的情形吞成空列表（真异常是它上一行的 `IndexError: list index out of range`），再包装成上面那句 OSError；`whisperx/alignment.py` 又包了一层。仓库名没错、模型也还在，**不需要改任何配置** |
| 为什么只有部分语种遇到 | 只有 **en/fr/de/es/it** 走 torchaudio（从 download.pytorch.org 取，不经过 HF）；**ja/zh/ko 等**走 HuggingFace（whisperx 的 `DEFAULT_ALIGN_MODELS_HF`）。列全部：`python -m core.align_model`。只下 PyTorch 权重约 **1.3 GB**（同仓库的 `flax_model.msgpack` 另 1.27 GB，**不必下**） |
| 三条出路 | ① **直接重试**：偶发问题，重新点一次「开始处理字幕」通常就过；② **项目自带预下载**：`python -m core.align_model ja`（自动换端点、可反复重跑，失败非零退出）；③ **手动下载放进项目**（见下，之后永久离线可用） |
| 代码 | `core/align_model.py`：本地目录优先 → 官方/hf-mirror 逐个试 → 全失败抛带指引的 `AlignModelUnavailable`（消息里有下载页、要哪些文件、放哪个目录）。`core/step2_whisperX.py` 的对齐那一步调它 |
| 回归 | `python -m unittest tests.test_align_model_fallback -v`（15 例，全离线，不 import torch） |

**手动下载放哪里**（浏览器能打开 hf-mirror 即可；放好后这一步永久离线可用）

1. 打开下载页：`https://hf-mirror.com/<仓库名>/tree/main`，例如
   <https://hf-mirror.com/jonatasgrosman/wav2vec2-large-xlsr-53-japanese/tree/main>
2. 下这几个文件（`README.md` / `.gitattributes` 无所谓，`flax_model.msgpack` 不要下）：
   `config.json`、`preprocessor_config.json`、`pytorch_model.bin`、`vocab.json`、`special_tokens_map.json`
3. 放进下面这个目录（不存在就自己建）：

```text
<项目根>\_model_cache\align\<语言代码>\
例：E:\VideoLingo\VideoLingoMove\_model_cache\align\ja\
```

> 判定标准（`core/align_model.py::local_align_model_ready`）：`config.json` 与
> `preprocessor_config.json` 必须都在，且 `pytorch_model.bin`（或 `model.safetensors`）
> **非空** —— 只判断"目录存在"会让下到一半的目录蒙混过关，之后报的还是那句难以定位的
> `Can't load feature extractor`。

**关于镜像与 `HF_ENDPOINT`（2026-09-20 实测，两个坑）**

| 结论 | 依据 |
| --- | --- |
| `HF_ENDPOINT` 只在**启动前**设才有效 | `huggingface_hub/constants.py`：`ENDPOINT = os.getenv("HF_ENDPOINT", …)`，**import 时读一次**（实测 0.36.2）。实验：import 之后把 `os.environ["HF_ENDPOINT"]` 设成一个不存在的域名，下载**照样成功**（说明运行时赋值被忽略）。所以 `core/step2_whisperX.py::check_hf_mirror()` 里那句运行期赋值**不生效**（它在 `import whisperx` 之后才跑）。要生效请在 `.bat`/shell 里先 `set HF_ENDPOINT=…` 再启动 |
| 别迷信镜像 | 同一台机器（代理 + 0.36.2）实测：官方端点 **3/3** 成功；`https://hf-mirror.com` 走 hub 下载 **4/4** 失败（`FileMetadataError: Distant resource does not seem to be on huggingface.co`）。浏览器能打开 hf-mirror 只代表"能手动下"，不代表 hub 客户端能下 |
| 因此 | `core/align_model.py` **不按 ping 选端点**（ping 通 ≠ HTTPS 能下），而是真去下载、失败就换下一个；要强制指定用 `--endpoint https://…`（可重复） |

### `Lightning automatically upgraded your loaded checkpoint from v1.5.4 to v2.6.6`（INFO，不是故障）

转录时经常能看到两行：

```text
2026-09-20 13:10:09 - whisperx.vads.pyannote - INFO - Performing voice activity detection using Pyannote...
Lightning automatically upgraded your loaded checkpoint from v1.5.4 to v2.6.6. To apply the upgrade to
your files permanently, run `python -m lightning.pytorch.utilities.upgrade_checkpoint <…>\whisperx\assets\pytorch_model.bin`
```

| 项 | 内容 |
| --- | --- |
| 第一行是什么 | WhisperX 的 **VAD**（人声活动检测）：转录前先用 pyannote 把音频切成"有人声/没人声"的区间。正常 INFO（`whisperx/vads/pyannote.py`） |
| 第二行是什么 | 那个 VAD 权重是 whisperx **自带**的 `whisperx/assets/pytorch_model.bin`（17.7 MB 的 pyannote 分割模型），它是 **PyTorch Lightning 1.5.4** 时代存的；现在环境里是 **2.6.6**（随 pyannote.audio 4.0.7 一起装进来的），于是 pyannote 加载时 Lightning **在内存里**把它迁移到新格式，并 INFO 一句"你也可以把升级永久写回文件"。发出位置：`lightning/pytorch/utilities/migration/utils.py:154` |
| 影响 | **没有**。迁移在内存里已经完成，模型正常加载、VAD 正常运行、转录正常出结果。每次新进程加载 VAD 会再迁移一遍，耗时几毫秒。`logs/videolingo_*.log` 里每次运行 1–2 条 |
| ⚠️ 它给的那条命令在本项目**会失败** | 直接跑 `python -m lightning.pytorch.utilities.upgrade_checkpoint <file>` → `_pickle.UnpicklingError: Weights only load failed … Unsupported global: GLOBAL omegaconf.listconfig.ListConfig`。原因和 `core/step2_whisperX.py::_patch_torch_load_weights_only` 那段注释是**同一个**：torch ≥ 2.6 把 `torch.load` 的 `weights_only` 默认值改成了 `True`，而 pyannote 的权重里含 omegaconf 对象。（2026-09-20 在**副本**上实测，副本是安全的试法） |
| 真想永久升级 | 先用同款垫片把 `weights_only` 改回 `False`，再跑那个模块。实测结果：版本号 `1.5.4 → 2.6.6`，pyannote 仍能正常加载该文件，运行时那句 INFO 消失，并且工具会**自动留一份 `.bak`**。命令见下 |
| 代价 / 值不值 | 改的是 `.venv\Lib\site-packages\whisperx\assets\` 里的文件：重装或升级 whisperx 会被覆盖回去；文件哈希与 pip 的 `RECORD` 不再一致（只影响卸载记录，不影响运行）。**收益只是少一行 INFO** —— 什么都不做完全没问题 |

```powershell
# 1) 先自己留一份备份（官方工具也会生 pytorch_model.bak）
Copy-Item .venv\Lib\site-packages\whisperx\assets\pytorch_model.bin $env:TEMP\vad_backup.bin -Force

# 2) 打上 weights_only 垫片后跑官方升级模块（等价于 core/step2_whisperX.py 里的那段垫片）
.venv\Scripts\python.exe -c @"
import sys, runpy, torch
_o = torch.load
torch.load = lambda *a, **k: _o(*a, **{**k, 'weights_only': False})
sys.argv = ['upgrade_checkpoint', r'.venv\Lib\site-packages\whisperx\assets\pytorch_model.bin']
runpy.run_module('lightning.pytorch.utilities.upgrade_checkpoint', run_name='__main__')
"@
```

> 想验证是否生效：`logs/videolingo_*.log` 里再跑一次转录，不应再出现那句
> `Lightning automatically upgraded…`；或直接读版本号
> `python -c "import torch;print(torch.load(r'.venv\Lib\site-packages\whisperx\assets\pytorch_model.bin',map_location='cpu',weights_only=False)['pytorch-lightning_version'])"`
> → 应打印 `2.6.6`。
>
> 另一种做法（不改 site-packages）：让项目把 `lightning.pytorch.utilities.migration.utils`
> 这个 logger 压到 WARNING。代价是连"确实发生了迁移"这个信息也一起没了，所以没默认做。

### `Request error ... Retrying (1/3)...` 然后 `Still failed after 3 attempts`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/ask_gpt.py`（`Request error ... Retrying` 在） |
| 根因 | 网络不可达 / base_url 或 key 错误 / 模型名不存在 |
| 处置 | 注意 base_url 拼接规则（`core/ask_gpt.py` 的 `fix_base_url`）：若 URL 里**任何位置**出现 `v1` 就原样使用，否则追加 `/v1`；另外**含 `ark` 的地址（火山方舟）会被归一化到它固定的 OpenAI 兼容端点**。所以 `https://api.deepseek.com` → `https://api.deepseek.com/v1`（正确）；`http://localhost:11434/v1` 已含 `v1`，保持不变（正确）；**而 `https://api.siliconflow.cn` → `https://api.siliconflow.cn/v1`**。若你的服务路径不是 `/v1`，需在 config 里写完整路径 |

### 控制台刷 `❎ json_repair parsing failed. Retrying: '''...'''`，但模型返回的明明是合法 JSON

| --- | --- |

## 六、字幕 / 时间轴类（step5~step7）

### `❎ 未找到与句子匹配的内容。`

| 项 | 内容 |
| --- | --- |
| 位置 | `core/step6_generate_final_timeline.py` |
| 根因 | 词级长串与句子文本**逐字符**精确匹配失败。常见原因：① 下游忘了把 `cleaned_chunks.xlsx` 的 `text` 去掉外层双引号（应 `.str.strip('"').str.strip`）；② 句子文件被人为编辑过；③ `step3` 的切分改变了字符（不只是空格/换行） |
| 处置 | 复现诊断（见下节「对齐诊断脚本」）；确认 `cleaned_chunks.xlsx` 的 text 是否带引号；一致后删 `output/*.srt` 重跑 step6 |
| 深入 | P1-3 |

### 字幕时间轴错位 / 字幕提前或延后

| 项 | 内容 |
| --- | --- |
| 根因 | ① `step5` 又切分了句子，但 `step6` 用切分后的文本重新匹配——正常会成功，若失败会报错；② 手工改过 `translation_results_for_subtitles.xlsx` 的 `Source` 列 |
| 处置 | 不要改 `Source` 列（它是匹配键），只改 `Translation`；删 `output/*.srt` 重跑 step6 |

### 字幕出现多行 / 单行过长

| 项 | 内容 |
| --- | --- |
| 根因 | `subtitle.max_length`（默认 75）与 `subtitle.target_multiplier`（默认 1.2）；`step5` 最多重试 3 轮切分，仍有超长会保留原样 |
| 处置 | 调小 `max_length` 会让切分更碎（增加 LLM 调用）；中文场景注意 `calc_len` 的加权规则（中日字符 1.75、韩 1.5） |

### 压制报 `字幕文件不存在，请先运行 step6 生成字幕。`

| --- | --- |
| 位置 | `core/step7_merge_sub_to_vid.py` |

| 处置 | 先跑 step6 |

### 成片只有 1 秒黑屏

| 项 | 内容 |
| --- | --- |

### 改了代码/参数，结果完全没变

按顺序检查五件事：

| 检查 | 命令 | 说明 |
| --- | --- | --- |
| ① 该步是否被幂等跳过 | 看控制台是否有 `already exists, skip` / `already exists, skipping` 字样 | 每个 step 都有跳过逻辑 |
| ② LLM 缓存是否命中 | `Remove-Item output\gpt_log\*.json` | 见「LLM/翻译类」 |
| ③ 火山 ASR 二级缓存是否命中 | UI 侧边栏底部的「🔧 火山 ASR 结果缓存」折叠区点「清空 ASR 结果缓存」；等价于 `Remove-Item output\log\asr_results\*.json` | 目录 `output/log/asr_results/`（`st.py`，属于 `cache_maintenance_section`）。**改了火山参数（模型版本/标点/DDC/ITN…）必须清这里**，否则会直接复用旧 JSON，表现为"改了参数没效果" |
| ④ 转录缓存是否命中 | UI 侧边栏底部的「♻️ 转录缓存」折叠区点「清空转录缓存」；等价于 `Remove-Item -Recurse -Force .cache\asr` | 目录 `.cache/asr/<key>/<part>.json`（`core/all_whisper_methods/transcription_cache.py`）。命中时控制台会打印 `♻️ 命中转录缓存：跳过音频分离与识别` 或 `♻️ 复用缓存分段 <start>_<end>`（`core/step2_whisperX.py`）。⚠️ 它**不在 `output/` 下**，所以「删除并重新选择」/ 归档 output 都不会清掉它（`.gitignore:159` 也是刻意这么排的） |
| ⑤ 下游产物是否还是旧的 | 按 [`../00-overview/02-数据流与中间产物.md`](../00-overview/02-数据流与中间产物.md) 的"想重跑删什么"表删文件 | — |

> 📌 转写缓存的身份是「源媒体内容 + ASR 设置 + 包版本」（`transcription_cache.py` 的 `cache_key`）：
> **换模型 / 换引擎（whisper↔volcano）/ 改识别语言 / 开关 demucs / 改火山那 10 个参数会自动失效**，
> 而改密钥、改文件名、改翻译设置**不会**失效（那是刻意的）。
