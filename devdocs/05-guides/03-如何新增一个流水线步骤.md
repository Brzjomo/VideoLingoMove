# 如何新增一个流水线步骤

以「在时间轴对齐后、压制前插入一步『字幕敏感词替换』」为例，给出可照做的清单。核心原则：**读上游产物、写新产物、遵守幂等约定、不破坏中间产物契约**。

> ⚠️ **编排结构已在「上游 3.0.4 合并」中改写**：`st.py` 里的 `process_text()` **已被删除**，
> 现在由 `build_task_steps()`（`st.py:69`）返回 `[(标签, 无参可调用对象), ...]` 交给
> `TaskRunner.start()`（`st.py:233`）在后台线程里顺序执行。第二节的插入方式据此重写。

---

## 一、设计前必须回答的 4 个问题

| 问题 | 为什么重要 |
| --- | --- |
| **插在哪两步之间？** | 决定输入/输出文件；同时检查你是否破坏了后面的依赖（例：若在 `step6` 之前改文本，`step6` 的逐字符匹配会失败，见 P1-3） |
| **输入是什么文件？** | 只能读上游**已经写好**的产物。对照 [`../00-overview/02-数据流与中间产物.md`](../00-overview/02-数据流与中间产物.md) |
| **输出写到哪里？** | 若是新产物 → 放 `output/log/`（结构化）或 `output/audio/`（音频）；若是**覆盖**上游产物 → 必须说明为什么不能新增文件（覆盖会破坏断点续跑） |
| **失败了怎么办？** | 现有步骤没有统一异常处理。`TaskRunner` 会捕获异常、把状态置为 `error` 并在页面上显示 `❌ 任务出错：<类型>: <信息>`（`st_components/task_runner.py:195-198`、`st.py:174-178`），但**后续步骤不会继续**。建议：可降级的操作自行 try/except 并打印告警（参考 `core/step6_generate_final_timeline.py:300-306` 的 `send_tanslation_complete_notification()`） |

## 二、改动清单（5 步，含编排配 2b / 2c）

### 步骤 1：新建模块

命名规范：`core/stepN_M_功能名.py`，其中 `N` 是它前面那一步的编号，`M` 是并列序号（现有先例：`step3_1` / `step3_2`）。

例如插在 step6 与 step7 之间 → `core/step6_1_replace_sensitive.py`。

模块骨架（照抄现有 step 的结构）：

```python
import os, sys
sys.path.append(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from rich import print as rprint
from core.config_utils import load_key

INPUT_FILE = 'output/trans.srt'
OUTPUT_FILE = 'output/log/sensitive_replaced.txt'

def replace_sensitive_main():
    # ① 幂等：产物存在即跳过
    if os.path.exists(OUTPUT_FILE):
        rprint(f"[yellow]⚠️ {OUTPUT_FILE} already exists, skipping.[/yellow]")
        return
    # ② 真正逻辑
    ...
    # ③ 写盘
    ...

if __name__ == '__main__':
    # ④ Windows 控制台默认 GBK；本模块若打印 emoji/中文，必须在入口修一次编码，
    #    否则 `python -m core.step6_1_replace_sensitive` 会抛 UnicodeEncodeError。
    #    现有 18 个带 __main__ 的 core 模块都这么写（照抄 core/step2_whisperX.py:540-548）。
    try:
        import easy_util as _eu
        _eu.ensure_utf8_console()
    except Exception:
        pass
    replace_sensitive_main()
```

> 📌 四条约定：**① 顶部 `sys.path.append` 指向项目根 ② 幂等检查在最前 ③ 提供 `__main__` 入口 ④ 入口调用 `ensure_utf8_console()`**。缺第③条就没法单步调试；缺第④条在 Windows 控制台下会直接崩在第一次打印 emoji 上。

### 步骤 2：在 `st.py` 的 `build_task_steps()` 里插入调用

打开 [`st.py`](../../st.py)，找到 `build_task_steps()`（`st.py:69`）。它返回一个
`[(标签, 无参可调用对象), ...]` 列表，`TaskRunner` 按顺序执行、并据此显示进度条与当前步骤名。

正确做法分两小步：

1. **先写一个无参包装函数**（和现有 `step_transcribe()` / `step_split_sentences()` / `step_summarize()` / `step_translate_and_burn()` 同级，`st.py:42-66`）：

```python
def step_replace_sensitive():
    step6_1_replace_sensitive.replace_sensitive_main()
```

2. **再把它作为一个元组插进 `build_task_steps()` 的列表**（`st.py:72-81`）：

```python
def build_task_steps():
    """按当前配置组装步骤列表。"""
    transcription_only = load_key("transcription_only")
    steps = [
        ("转录（Whisper / 火山 ASR）", step_transcribe),
        ("断句（spaCy + LLM）", step_split_sentences),
    ]
    # ……
    steps.append(("翻译并压制字幕", step_translate_and_burn))
    return steps
```

⚠️ 三点：
- **不要漏掉元组的第一个元素**：它是进度条上显示的步骤名（`st.py:123-126` 的 `st.progress(..., text=f"第 N/M 步：{label}")`）。传了裸函数会在 `for i, (label, func) in enumerate(...)` 处直接抛 `TypeError`。
- `build_task_steps()` 里 `transcription_only` 有两条分支（`st.py:76-80`）：直通模式只追加 `ensure_terminology_file()`，翻译模式才追加 `("术语提取", step_summarize)`。确认你的步骤是否**只应在一个分支里跑**。
- 包装函数必须**无参**（`TaskRunner._run()` 是 `func()` 调用，`st_components/task_runner.py:190`）。需要参数就用闭包或默认值。

**不要**在步骤内部读写 `st.session_state`：步骤跑在后台线程里（`st_components/task_runner.py:120`），
改 session_state 不可靠。需要"等用户确认"就用 `TaskRunner.request_review_pause()`
（`st_components/task_runner.py:81`），UI 侧由 `task_control_panel()` 渲染确认界面。

### 步骤 2b：给长循环加取消钩子（若你的步骤会跑很久）

`TaskRunner` 的暂停/停止是**协作式**的：它只能在线程调用 `easy_util.check_cancel()`
（`easy_util.py:231` → `TaskRunner.check_cancel()`，`st_components/task_runner.py:58`）
或步骤之间（`st_components/task_runner.py:177-186`）生效。若你的步骤内部是一个长循环，
请在循环里调用：

```python
import easy_util as eu
...
for item in items:
    eu.check_cancel()   # 暂停时阻塞，停止时抛 StopTask
    do_one(item)
```

现有接入点共 3 处：`core/step2_whisperX.py:500`（分段循环）、`core/step4_2_translate_all.py:125`
（`as_completed` 循环）、`core/translate_once.py:30`（`translate_lines()` 入口）。没有活跃任务时
（直接命令行跑脚本）它是空操作。

### 步骤 2c：不要绕过 concurrency 的清理

若你的步骤自己也用 `ThreadPoolExecutor`，请照 `core/step4_2_translate_all.py:121-135` 的写法：
捕获 `BaseException` 后对所有 pending future 调 `cancel()` 再 `raise`，否则线程池退出时的
`shutdown(wait=True)` 会让"停止"要等所有排队任务跑完。

### 步骤 3：在 `imports_and_utils.py` 注册模块

[`st_components/imports_and_utils.py`](../../st_components/imports_and_utils.py) 的 `from core import (...)` 列表（`:3-18`）按注释分成了 **3 组**：Download & Transcribe / Text Processing & Analysis / Subtitle Timeline & Merging（配音相关的 Audio Generation、Final Video Composition 两组随配音链路删除）。把你的模块加到对应组里——**这是最容易忘的一步**，忘了 `st.py` 里会在运行时 `NameError`。

### 步骤 4：（可选）加配置开关

若步骤需要开关：

```yaml
# Whether to replace sensitive words in subtitles
replace_sensitive: false
```

然后在模块里 `load_key('replace_sensitive')` 决定是否执行。规范见 [`../04-interfaces/01-配置文件与参数.md`](../04-interfaces/01-配置文件与参数.md)。

### 步骤 5：（可选）加 UI 控件

若要在侧边栏暴露开关，改 [`st_components/sidebar_setting.py`](../../st_components/sidebar_setting.py)，照抄同类 `st.checkbox` + `update_key` 的写法。

## 三、如果新步骤要改变"阶段完成"的判据

UI 现在只判断**一个字幕阶段**（配音阶段已删除），判据是 step7 写下的显式完成标记，而**不是**成片是否存在：

| 阶段 | 判据 | 位置 |
| --- | --- | --- |
| 字幕完成 | `output/log/subtitle_stage_done.txt` 存在（常量 `STAGE_DONE_MARKER`，由 `_mark_stage_done()` 写出） | `core/step7_merge_sub_to_vid.py:40`、`:49`；消费方 `st.py:25-33` 的 `subtitle_stage_finished()` |
| 成片（附加条件） | `output/output_sub.mp4` 存在**且** `resolution != '0x0'` 时才嵌入播放器 | `st.py:241` |

为什么不用成片存在作为判据：`resolution: '0x0'` 且输入是真实视频时，step7 **有意不生成**任何成片（见
[`04-已知问题与技术债.md`](04-已知问题与技术债.md) 的 G5）；只看成片会让界面永远停在"开始处理字幕"按钮上。

若你的步骤加在**末尾**（阶段完成之后），UI 不会给你任何入口——需要同时改这个判据或新增一个区块。
参考 [`../04-interfaces/02-Streamlit界面组件.md`](../04-interfaces/02-Streamlit界面组件.md)。

## 四、如果新步骤要"替换"而不是"插入"

替换某一步时，只需保证**产物契约不变**。举例：把 `step2` 换成别的 ASR，只要仍写出 `output/log/cleaned_chunks.xlsx`（列 `text`/`start`/`end`，且 `text` 值带双引号），后面的步骤完全不用改。

这体现了本项目的核心设计（磁盘即契约）：

```mermaid
flowchart LR
    A["上游步骤"] -->|"写 output/log/xxx.xlsx"| B["你的新步骤"]
    B -->|"写同路径同 schema"| C["下游步骤\n无需任何改动"]
```

⚠️ **双引号契约**：`save_results()` 写 `cleaned_chunks.xlsx` 时会把 `text` 包成 `f'"{x}"'`，下游统一用 `.str.strip('"').str.strip()` 剥离。若你替换了生产者，**要么保持这个怪癖，要么同时修改所有消费者**（grep `.strip('"')` 找到它们）。

## 五、验证清单

| 检查项 | 方法 |
| --- | --- |
| 幂等 | 连跑两次，第二次应打印"跳过"且产物 mtime 不变 |
| 单步可跑 | `python -m core.step6_1_replace_sensitive` |
| UI 连通 | 从页面点按钮跑完整阶段，确认不报 `NameError`，且进度条上的步骤名是你写在元组里的标签 |
| 暂停/停止 | 在页面上点「⏸️ 暂停」应停住（`TaskRunner.check_cancel()` 生效），点「⏹️ 停止」应在下个检查点退出 |
| 幂等链完整 | 删掉你的产物，重跑，确认上游不会被重复执行（上游产物还在，应跳过） |
| 断点续跑 | 跑到一半点「⏹️ 停止」（**不是** Ctrl+C 杀进程），再点一次按钮，应从你的步骤继续（因为上游产物都在） |
| 回归测试 | 若新增了可单测的逻辑，放进 `tests/`（标准库 `unittest`，不新增依赖），跑 `python -m unittest discover -s tests -v` |
