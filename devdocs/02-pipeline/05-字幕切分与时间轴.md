# 字幕切分与时间轴对齐（step5 / step6）

## 一、职责与边界

step5 把「句子级」的双语行按长度上限再切碎成「字幕级」；step6 用 word 级时间戳给每一行字幕重新分配起止时间并写出 SRT。

- **负责**：① step5 `split_for_sub_main()` 判定哪些行超长（源文按字符数、译文按加权长度 × `target_multiplier`），按「纯本地 / 机械等分 / LLM 对齐」三条分支把一行拆成 2 段并对齐译文，最多重试 3 轮，产出 `output/log/translation_results_for_subtitles.xlsx`；② step6 `align_timestamp()` 把句子文本沿 word 级时间戳做**单调子串匹配**（精确匹配失败时按 `subtitle.align_on_mismatch` 决定「模糊兜底并告警」还是「抛错」），得到 `(start, end)` 与 `duration`，缝合 <1 秒的空隙，格式化 SRT 时间戳，并按 4 种列组合写出 `output/src.srt`、`trans.srt`、`src_trans.srt`、`trans_src.srt`；③ `core/json_to_subtitle.py` 作为旁路工具，把 ASR 的 JSON 直接转成 SRT 与 `cleaned_chunks.xlsx`。
- **不负责**：step5 **不写任何 SRT**（这是常见误解，见 5.1）；step6 **不写** `output/audio/*_subs_for_audio.srt`（那套配置已随配音链路删除，见 [`07-配音音频生成.md`](07-配音音频生成.md)）；字幕烧录在 step7。

## 四、关键数据结构

### 4.1 三次时间映射（Word 级 → sentence 级 → subtitle 级）

| 层级 | 载体文件 | 字段 | 类型 / 单位 | 产生者 |
| --- | --- | --- | --- | --- |
| ① Word 级 | `output/log/cleaned_chunks.xlsx` | `text`, `start`, `end` | `text` 为带双引号的 word 字符串；`start`/`end` 为 float **秒** | step2 `whisperX_utils.save_results()`（`core/all_whisper_methods/whisperX_utils.py:290-291`）或 `json_to_subtitle.generate_excel_from_segments()` |
| ② Sentence 级 | `output/log/translation_results.xlsx` | `Source`, `Translation`, `timestamp`, `duration` | `timestamp` 是 `HH:MM:SS,mmm --> HH:MM:SS,mmm` **字符串**；`duration` 为 float **秒** | step4.2 `translate_all()`（`core/step4_2_translate_all.py:177`） |
| ③ Subtitle 级 | `output/log/translation_results_for_subtitles.xlsx` → `output/*.srt` | `Source`, `Translation`；SRT 的序号/时间行/文本行 | 时间轴继承自 ②，按切分后**逐行重算**（行数变多，时间被重新分配） | step5 `:189` → step6 `:252-257` |

映射规则：①→② 由 `get_sentence_timestamps()` 把「句子文本」在「word 拼接串」中子串匹配，取首词 `start` 与末词 `end`；②→③ 由 step5 在一行内部插 `\n` 拆成多行，**拼接文本不变**，所以 step6 重跑同一套匹配即可把时间重新分配到更细的粒度。

实测对照（示例数据，非推断）：`output/log/cleaned_chunks.xlsx` 当前为 23000 个 word 行、列为 `text`/`start`/`end`，中文逐字且带双引号（如 `"那"`）。

### 4.2 SRT 文本结构

`generate_subtitle_string()`（`core/step6_generate_final_timeline.py:232-250`，定义在 `align_timestamp()` 内部）逐行拼接：

```text
{i+1}
{row['timestamp']}
{line1}
{line2}

```

- `columns` 只有 1 列时只写 `line1` 再补一个 `\n\n`（`:248-249`），**不再产生空的第二行**（历史缺陷 P3-9 已修）；`src.srt` / `trans.srt` 与 `src_trans.srt` / `trans_src.srt` 的块间都恰好是 1 个空行。
- 文本中的连续空白会被压成单个空格（`:243`、`:246`）。
- 整个字符串最后 `.strip()`（`:250`），因此文件末尾没有多余空行。

### 5.3 `get_sentence_timestamps()` 与 `_fuzzy_find()` 的对齐算法

```text
输入：df_words = cleaned_chunks.xlsx（text/start/end，word 级）
      df_sentences = 待对齐的 DataFrame（列名必须是 'Source'，按 index 顺序遍历）
      on_mismatch = 'warn'（默认：模糊兜底 + 告警） | 'strict'（精确匹配失败即抛错）

① 构造全词串 full_words_str = concat( remove_punctuation(word.lower()) )   # :126-131
   同时建立 position_to_word_idx：每个字符位置 → 所属 word 的行号
   （word_idx_at(pos) 在越界时退到最近的已知位置，# :133-139）
② 逐句顺序扫描（current_pos 单调递增，不回溯，逐位比较）                  # :141-163
   clean_sentence = remove_punctuation(sentence.lower()).replace(" ", "")   # :143
   命中则取
     start = df_words['start'][首词行号]，end = df_words['end'][末词行号]   # :149-155
   命中后 current_pos += sentence_len（保证句子与句子不重叠、保持音频顺序）
③ 未命中：
   - on_mismatch == 'strict' → 打印警告 + show_difference + raise ValueError  # :165-169
   - 否则走 _fuzzy_find() 兜底（# :172-191）：
     a. 用句子前缀在词串中 find()（锚长 24/16/8/4 依次尝试），命中则按句子长度截一段
     b. 前缀找不到 → 取最长公共块，按块在句中的位置按比例外扩
     c. 仍失败（例如清洗后为空串）→ 沿用上一个词的结束时间，记为相似度 0
   兜底后 current_pos = max(current_pos, end_pos)                            # :190
④ 只要发生过兜底就打印「共 N/M 条字幕未精确匹配，已使用兜底对齐」与最多 10 条明细  # :193-200
```

关键约束（都是隐式契约）：

| 约束 | 依据 | 违反后果 |
| --- | --- | --- |
| 句子的归一化文本**应当**是全词串的**连续子串**，且**顺序与音频一致** | `:141-163` 单调扫描 | `strict` 下抛 `ValueError`、整个 step6 中断；`warn`（默认）下模糊兜底并告警，但**兜底前进的词位可能偏移，造成后续句子连锁失配** |
| 句子侧删掉了**所有空格**（`.replace(" ", "")`），word 侧只做首尾 `strip()` | `:143` vs `:44` | 若某个 word token 内部含空格（例如没有词级时间戳时 `json_to_subtitle` 用整段文本兜底，`core/json_to_subtitle.py:143-151`），全词串会混入空格 → 位置错位甚至落到兜底路径 ⚠️ |

## 七、技术要点与坑

### 7.1 `calc_len()` 的权重与注释不一致

`core/step5_splitforsub.py:42-43` 的注释写「Chinese and Japanese 2.5 characters, Korean 2 characters, Thai 1.5 characters, full-width symbols 2 characters」，而 `:48-57` 的实际返回是 **CJK/日文假名 1.75、韩文 1.5、泰文 1、全角符号 1.75、其他 1**。改 `max_length` 或 `target_multiplier` 时以**代码**为准。

另一个细节：`。`(U+3002)、`、`(U+3001) 落在 `0x3002`/`0x3001`，**不属于**任何判定区间（`:48-55` 只覆盖 `0x3040-0x30FF` 假名与 `0xFF01-0xFF5E` 全角）→ 按 1 计权；而 `，`(U+FF0C) 属全角 → 1.75。

### 7.2 单行切分失败**不会**静默丢失（历史缺陷已修）

```python
# core/step5_splitforsub.py:153-156
with concurrent.futures.ThreadPoolExecutor(max_workers=load_key("max_workers")) as executor:
    # 必须消费 map 的返回值：executor.map 是惰性的，不迭代就不会取回结果，
    # 工作线程里的异常会被完全吞掉（见 devdocs 已知问题 P3-6）。
    list(executor.map(process, to_split))
```

- `executor.map()` 返回的是**惰性迭代器**，历史上没有 `list()` 它，于是 `process()` 内抛出的异常不会冒泡（`Future` 的异常只在取结果时重抛），该行**保持未切分却没有任何日志**（历史缺陷 P3-6）。现在返回值被 `list()` 消费，且 `process()` 内部自带 `try/except`（`:145-148`）：出错时打印 `⚠️ 第 {i} 行切分失败（保留原行）: {类型}: {信息}` 并保留原始行。
- 保留原行的后果仍在：失败行不会被切开，三轮重试后可能写出**超过 `max_length` 的字幕行**——但现在**一定有日志**。排查方法是看控制台告警，或自己重算 `calc_len()`（见第九节）。
- 仍然会触发失败的两类场景：① `align_subs` 里 `item[f'target_part_{i+1}']` 遇到 LLM 少返回一项 → `KeyError`；② `get_joiner(language)` 遇到两张语言表都不含的语言码（如 `th`）→ `ValueError`（`core/config_utils.py:171`）。

### 7.3 切分与时间轴之间的耦合

| 关系 | 事实 | 风险 |
| --- | --- | --- |
| 切分**不破坏**对齐 | `split_sentence()` 只在**原字符串内部插入 `'\n'`**（`core/step3_2_splitbymeaning.py:80-87`），`align_subs` 返回 `src_part.split('\n')`（`core/step5_splitforsub.py:75`） | 拼接文本与切分前逐字符相同 → step6 的单调子串扫描仍能命中，这是「先 step5 再 step6」能工作的**根本前提**；一旦有人改成「改写句子再切分」，step6 立刻落到模糊兜底（`warn`）或抛 `ValueError`（`strict`） |
| 时间**只**来自 Source | `get_sentence_timestamps()` 只用 `df_sentences['Source']`（`:142`）；`Translation` 不参与位置计算 | 译文长短、段数与源文不一致**不会**让时间轴错位，但会让「字幕内容与时间区间」语义错配（观众视角的错位） |
| 粒度变化必须**同时**重算 | step5 改变了行数，step6 依赖行数逐行生成时间 | 只重跑 step5 而 `translation_results_for_subtitles.xlsx` 与新 `translation_results.xlsx` 不匹配时，Source 序列对不上 → 大量单词兜底告警（`warn`）或 `ValueError`（`strict`）；两个 xlsx 必须来自同一次 step3/step4 |
| trim 在切分**之前** | `check_len_then_trim` 在 `core/step4_2_translate_all.py:174` 执行，step5 读的是 trim 后的译文 | 若把 trim 挪到 step5 之后，step5 的长度判定就会基于未裁剪的更长文本 → 字幕偏短/超长判断失真 |
| 词级数据换了就全盘错位 | `cleaned_chunks.xlsx` 若被重跑 step2 覆盖 | 词序列变化 → 老的行文本匹配不上 → 兜底告警铺满控制台（这是保护，不是静默错位） |

| 切分是否真的发生 | 比较 `translation_results.xlsx` 与 `translation_results_for_subtitles.xlsx` 的行数 | 后者 ≥ 前者；若相等说明没有任何行超长 |
| 是否留下超长行 | 对 `translation_results_for_subtitles.xlsx` 用 `calc_len()` 重算：`len(src) <= 75` 且 `calc_len(tr)*1.2 <= 75` | 全部满足；不满足的行按 7.2 查控制台告警与 `output/gpt_log/align_subs.json` |
| 对齐是否有兜底 | 观察 step6 控制台 | 正常应**不**出现 `⚠️ 共 N/M 条字幕未精确匹配`；出现即说明有句子没对上，需人工抽查 `output/trans.srt`（`align_on_mismatch: strict` 时则直接抛 `ValueError`） |
| 时间轴单调 | 解析 `output/trans.srt` 的时间行 | 每行 `start < end`，且下一行 `start >= 上一行 start` |
| 条目数一致 | `output/trans.srt` 的块数 vs `translation_results_for_subtitles.xlsx` 行数 | 相等（`generate_subtitle_string()` 逐行输出） |
| SRT 可被 ffmpeg 接受 | `ffmpeg -v error -i output/trans.srt -f null -` | 无报错输出 |
| 单列 SRT 的块间空行 | `Get-Content output\trans.srt -TotalCount 6` | 单列配置的块间恰好 1 个空行（P3-9 已修） |
