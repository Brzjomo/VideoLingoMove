## 二、硬性前置条件

| 项 | 要求 | 为什么 |
| --- | --- | --- |
| Python | **3.10–3.13（推荐 3.11）** | `installer.py` 的闸门是 `PYTHON_MIN/PYTHON_MAX = (3,10)~(3,14)`，`setup_env.py` 的 `SUPPORTED_PYTHONS` 是 3.10–3.13，默认取 3.11。**不再有"3.12 装不上 torch"的限制**：torch 已升到 2.8.0，cp310–cp313 的 wheel 齐全 |
| 解释器 | **项目内 `.venv`（首选）→ conda `videolingo` → PATH 上的 python** | 三个启动脚本用同一套探测顺序（`.venv\Scripts\python.exe` → `%USERPROFILE%\anaconda3\envs\videolingo\python.exe` → `python`），命中 conda 时**直接调用该环境的 `python.exe`**，不再 `call activate.bat`。判据是实际执行 `sys.version_info` 检查，而不是 `if exist` |
| `.venv` 的宿主 | **项目内 `.python\`**（`setup_env.py` 自动装/复用） | venv 只存 site-packages，**标准库和 `python3XX.dll` 从 `pyvenv.cfg` 的 `home` 读**。若宿主指向项目外（例如别的项目里的 python），那个项目一挪本项目就废，traceback 里也会出现别人的路径。`Install.bat` / `setup_env.py` 都会把 `UV_PYTHON_INSTALL_DIR` 指到 `<项目>\.python`，并用 `--python <解释器路径>` 建 venv；详见 [`../06-batch-and-tools/02-安装脚本与依赖.md`](../06-batch-and-tools/02-安装脚本与依赖.md) 的 5.11.1 |
| FFmpeg | **大版本必须是 4–7**，且必须是**带共享库的构建**（bin 目录里有 `avcodec-*.dll`） | `torchcodec` 走 FFmpeg 共享库解码。⚠️ gyan.dev 的 `full_build` 是**静态**构建，虽然版本号合规但 `torchcodec.decoders` 会加载失败；BtbN 的 **shared** 包才行。若环境里已有合规版本，安装脚本会跳过下载；否则取一份放进项目内 `ffmpeg\`，运行期由 `runtime_libraries.py` 自动接入（不需要改 PATH，也不需要重启终端） |
| CUDA + cuDNN | **不需要手工安装** | CUDA 版 PyTorch 的 wheel 自带所需的 CUDA 运行库，只要显卡驱动足够新。`installer.py` 按 `nvidia-smi` 报的算力自动选后端：<7.0 → cu126、7.0–11.x → cu128、≥12.0 → cu129、无 N 卡 → CPU |
| 磁盘 | ≥ 30 GB 空闲 | 一个 30 分钟视频会产生 `raw.wav`(170MB) + `raw.mp3`(86MB) + `for_whisper.mp3`(65MB) + 模型缓存数 GB；torch 单个 wheel 就有 2.7–3.6 GB |
| **工作目录** | **必须是项目根目录** | 全代码使用相对路径 `output/...`、`config.yaml` |

## 三、安装

```powershell
# 最快路径：双击 Install.bat（或在本目录运行）。可反复运行，已装好的会跳过。
Install.bat

# 网络不佳时：先只拿下载地址，用外部工具下好放进 _downloads\，再重跑
Install.bat --download-only
Install.bat
```

`Install.bat` 做的四件事：① 准备 Python 3.11（依次尝试复用 `.venv` → `py` 启动器 → PATH 上的 python → 让 uv 下载 → `winget` → 官方安装包静默安装）；② 装 **uv**；③ 建项目内 `.venv` 并把模型与下载缓存都指向项目内；④ 装依赖 + 体检 + 跑单元测试。

手工等价步骤：

```powershell
# 建项目内 .venv + 装依赖（uv；缺失时回退标准库 venv 并警告无法自选 Python 版本）
python setup_env.py --python 3.11

# 体检（--smoke 会逐个 import whisperx/torchcodec/pyannote 等）
python installer.py --check --smoke

# 想先看清楚会装什么（不改动任何东西）
python installer.py --dry-run
```

`installer.py` 的真实执行顺序（`installer.py: main`）：

1. `--check` 时只跑 `health_check` 并以「错误条数」决定退出码，不做任何安装。
2. 引导依赖：仅当 `import rich` 失败时 `pip install requests rich ruamel.yaml`。
3. `python_ok` —— 版本必须在 `PYTHON_MIN/PYTHON_MAX = (3,10)~(3,14)` 之间，否则直接退出 1。
4. `ensure_ffmpeg` —— `ffmpeg` 与 `ffprobe` 缺任一即报错；**先看项目内 `ffmpeg/`，再看系统 PATH，都合规就跳过下载**，都没有才去解析 BtbN 的 release 资产并解压（`resolve_ffmpeg_url` 查 GitHub Releases API，离线/内网可用 `VIDELINGO_FFMPEG_URL` 覆盖），并校验**大版本在 4–7**。
5. `maybe_configure_mirror(args.auto_mirror)` —— **默认不改动你全局的 pip 配置**，只有显式 `--auto-mirror` 才会调用 `core.pypi_autochoose.main`。
6. **安装状态指纹**：`requirements_hash`（`requirements.txt` 内容 + `torch` 版本）与 `sys.prefix/.videolingo-install.json` 一致就跳过整段安装；否则 `install_torch`→ `pip install -r requirements.txt` → `write_state`。
7. `install_torch` 真的按硬件选 wheel：`detect_gpu_compute_cap` 走 `nvidia-smi --query-gpu=compute_cap`，再由 `TORCH_SPECS` 映射到 **cu126 / cu128 / cu129 / cpu** 四个索引之一（老驱动没有该字段时回退到按型号匹配的算力表）。三件套（torch/torchaudio/torchvision）都从对应 `--index-url` 装；`_downloads/` 里有匹配的本地 wheel 时优先用文件路径安装。
8. Linux 才执行 `install_cjk_fonts` —— 按发行版装 `fonts-noto-cjk` / `google-noto-sans-cjk-fonts` / `noto-fonts-cjk`（原来的 `fonts-noto` 不含中日韩字形）。
9. 收尾再跑一次 `health_check`；有错则退出 1。
10. 带 `--launch`（`install.py` 默认加）时转调 `launch.py`。

> ⚠️ `install.py` 是 19 行的向后兼容包装（`from installer import main`），默认补 `--launch`，所以它末尾会自动启动应用；只想装依赖请加 `--no-launch` 或手动中断。
> 💡 常用开关：`--force`（忽略状态指纹重装）、`--auto-mirror`（显式允许切 pip 镜像）、`--torch-backend`（手工指定 cu126/cu128/cu129/cpu）、`--python`、`--dry-run`、`--smoke`、`--download-only`、`--download-dir`、`--no-launch`。重复运行安装脚本不会再重装几个 GB 的依赖。脚本**全程非交互**，因此没有 `--yes`。

> 🧹 **装完想清理旧环境 / 释放 C 盘**：`Cleanup.bat`（或 `python cleanup.py`）。
> 默认**只扫描报告、不删任何东西**；`--clean` 清 pip/uv 下载缓存，`--clean --models` 额外清 HuggingFace/torch 模型缓存，
> `--clean --models --all` 再加项目内 `_downloads\` 与 `ffmpeg\`。详见 [`../06-batch-and-tools/02-安装脚本与依赖.md`](../06-batch-and-tools/02-安装脚本与依赖.md)。

## 四、启动

| 目标 | 命令 | 说明 |
| --- | --- | --- |
| Web 交互模式（推荐） | `python launch.py` | 先预检（缺包 / 缺 ffmpeg / 端口占用），再写一份运行日志到 `logs/videolingo_<时间戳>.log` |
| Web 交互模式（原样） | `python -m streamlit run st.py` 或双击 `OneKeyStart.bat` | 默认 <http://localhost:8501>（`.streamlit/config.toml` 只设了 `maxUploadSize = 4096` 与 `[client] toolbarMode = "viewer"`，未改端口） |
| 只做启动预检 | `python launch.py --no-log` | 只打印 errors / notes 并返回退出码，不启动服务 |
| 批处理模式 | `cd batch && StartBatch.bat`（脚本内 `cd ..` 回到根目录后运行 `streamlit run batch\utils\gui.py`） | **同样是 Streamlit 应用**，不是桌面 GUI |
| 批量音频提取工具 | `cd AudioExtract && Start.bat` | 独立小工具 |

`launch.py: preflight`会检查：`streamlit`/`json_repair`/`torch` 能否 import、`ffmpeg` 与 `ffprobe` 是否在 PATH、端口是否已被占用；另外把「CUDA 不可用 / 未装 whisperx / 尚无 config.yaml」作为**提示**（不阻止启动）打印出来。可用 `--port 8502` 换端口。

`st.py` 的启动期初始化很关键：

```python
current_dir = os.path.dirname(os.path.abspath(__file__))
if current_dir not in os.environ['PATH'].split(os.pathsep):
 os.environ['PATH'] += os.pathsep + current_dir # 让 `ffmpeg` 命中根目录的 ffmpeg.exe
if current_dir not in sys.path:
 sys.path.append(current_dir)
```

`st.py` 还会先调一次 `eu.ensure_utf8_console`，把控制台输出切成 UTF-8（Windows 默认 GBK，打印 emoji 会抛 `UnicodeEncodeError`）。

## 五、必须配置的项目（否则跑不动）

编辑 `config.yaml`：

| 键 | 说明 |
| --- | --- |
| `api.key` / `api.base_url` / `api.model` | **真正生效的 LLM 配置**（`core/ask_gpt.py` 只读 `api`）。`deepseek_api` / `qwen_api` / `siliconflow_api` / `ollama_api` 是 sidebar 用来一键切换的**预设池**，它们通过 `assign_key` 写入 `api` 后才生效 |
| `whisper.language` | 源语言；`zh` 会强制使用 Belle 中文标点模型；`auto` 走自动检测。**这是源语言的唯一权威键**：`update_key("whisper.language", <非 auto>)` 会原子同步写 `whisper.detected_language`（`core/config_utils.py`），`auto` 时不覆盖 |
| `whisper.detected_language` | ASR 写回的实际识别语言（`whisperX_utils.save_language`，过滤 None/空串/`auto`）。**只在 `whisper.language == "auto"` 时作为回退**被 `core/config_utils.get_source_language` 读取 |
| `whisper.model` | 非中文时使用的模型 |
| `whisper.cache` | 转录缓存开关（默认 `true`）。**`config.example.yaml` 里还没有这个键**，需要时手工在 `whisper:` 下加一行 `cache: false`；缺失时 `core/step2_whisperX.py` 用 `load_key_or("whisper.cache", True)` 取默认值 |
| `youtube.cookies_path` / `youtube.proxy` | 新增的 YouTube 下载设置。`cookies_path` 填 Netscape 格式 cookies.txt 路径；`proxy` 留空串=显式禁用代理，`null`/缺省=交给 yt-dlp 自动发现，URL=强制使用（`core/step1_ytdlp.py`） |
| ~~`tts_method` + 对应引擎的 key~~ | **已随配音链路删除**，`config.example.yaml` 中不再存在；读它会抛 `KeyError`。整个配音链路（`core/step8_*`~`step12_*`、`core/all_tts_functions/`）与对应文档均已移除，需要历史实现请查 git 历史 |
| `llm_sentence_split` | 是否用 LLM 优化断句（默认 `true`）。**只在 `transcription_only: true` 时可关闭**；翻译模式下侧边栏不显示该开关并强制写回 `true`。关闭后 `step3_2` 直接输出 spaCy 结果、`step5` 按标点机械断开，整条链路零 LLM 调用。判定入口 `core.config_utils.use_llm_sentence_split` |
| `transcription_only` | 只要字幕不要翻译时设 `true` |

⚠️ **安全**：`config.yaml` 含真实密钥，且已被 `.gitignore` 忽略（未被 git 跟踪，已核对）。密钥也可以完全不落盘：`load_key` 优先读环境变量 `VIDEOLINGO_<KEY>`（如 `api.key` → `VIDEOLINGO_API_KEY`），并可展开值里的 `${VAR}`。详见 [`../03-subsystems/01-LLM调用与提示词.md`](../03-subsystems/01-LLM调用与提示词.md) 的「安全提醒」小节。

> 📌 本文只引用**键名**，不引用 `config.yaml` 的行号 —— 它是本机文件，行号会随编辑漂移。
> 需要定位时用 `grep -n '键名' config.yaml`，或直接对照模板 `config.example.yaml`。

## 六、最小可用验证路径

不要一上来就跑完整流程。按下表逐级验证：

| 级别 | 操作 | 通过标准 |
| --- | --- | --- |
| L0 环境体检 | `python installer.py --check` | 逐项列出缺失的包 / ffmpeg / ffprobe；**全通过时退出码 0**，有错误时 1 |
| L0b 启动预检 | `python launch.py --no-log` | 打印 errors / notes 后退出，不启动服务 |
| L0c 回归测试 | `python -m unittest discover -s tests -v` | **12 个文件 / 242 例全绿**（标准库 `unittest`；多数用例是纯逻辑 + `FakeTorch` 桩，不需要 torch/spacy/网络） |
| L1 配置 | `& $py -c "from core.config_utils import load_key; print(load_key('api'))"` | 打印出 api 字典 |
| L1b 源语言 | `& $py -c "from core.config_utils import get_source_language; print(get_source_language)"` | 打印语言码；两个语言键都不可用时明确抛 `ValueError` |
| L2 上传/下载 | UI 上传一个 < 1 分钟短视频（或音频） | `output/` 下出现素材文件，页面出现播放器；并生成 `output/input_manifest.json` |
| L3 转写 | 只跑 step2（见下节命令） | 生成 `output/log/cleaned_chunks.xlsx`，行数 ≈ 词数；同时出现 `.cache/asr/<key>/complete.json` |
| L4 对齐 | 跑 step6 | `output/trans.srt` 的序号连续、时间递增 |
| L5 成片 | 侧边栏打开 **烧录字幕（压进成片）** 后跑 step7 | `output/output_sub.mp4` 可播放且字幕正常（**输入为音频时不会产出成片，属预期**） |
| L6 交付 | 点「下载所有字幕」 | `output/<视频名>.srt` 与 `<视频名>.txt` 存在，zip 内 6 个条目 |

> `$py` = `<项目>\.venv\Scripts\python.exe`（由 `Install.bat` / `setup_env.py` 建出）。
> 装不出 `.venv` 时才回退旧的 conda 环境：`"$env:USERPROFILE\anaconda3\envs\videolingo\python.exe"`
> —— 但那是**升级前的老栈**（torch 2.1.2 / streamlit 1.38 / spacy 3.7），只适合跑不依赖新栈的单元测试，
> **不能**用来跑本分支的 `st.py`。
> L0c 是**改完代码后最快的护栏**：`tests/` 下 12 个文件分别锁住源语言解析、提示词契约、输入判定/产物过滤、音频抽取参数、转录缓存身份、批量路径、清理工具、torch 后端选择、`torch.load` 垫片语义、Streamlit 宽度 API 卫生、**对齐模型的多端点回退与失败提示**、`asyncio` 关网页噪声过滤与体检裸 import 静音、`package_version` 取版本。

## 七、单步调试（最重要的技巧）

每个 `core/stepN_*.py` 都有 `if __name__ == '__main__':` 入口，可以单独跑：

```powershell
# 必须 cd 到项目根目录
cd E:\VideoLingo\VideoLingoMove
$py = ".venv\Scripts\python.exe"

& $py -m core.step2_whisperX # 转写
& $py -m core.step3_1_spacy_split # NLP 切分
& $py -m core.step3_2_splitbymeaning # LLM 语义切分
& $py -m core.step4_1_summarize # 术语总结
& $py -m core.step4_2_translate_all # 翻译
& $py -m core.step5_splitforsub # 字幕长度切分
& $py -m core.step5_2_polish_subs # 字幕润色（可选，需先开 subtitle.polish_translation）
& $py -m core.step6_generate_final_timeline # 生成 SRT
& $py -m core.step7_merge_sub_to_vid # 压制字幕（Burn-in 关闭或音频输入时静默跳过）
```

> 💡 用 `& $py -m core.xxx` 而不是 `& $py core/xxx.py`：两者都能跑（模块内都有 `sys.path.append`），但 `-m` 形式更接近 Streamlit 的导入方式，能更早暴露 import 问题。
> 💡 这些模块的 `__main__` 入口都会先调 `easy_util.ensure_utf8_console`，所以**不再需要**手动设 `PYTHONIOENCODING`（设了也无害）。这个修复覆盖 18 个带 `__main__` 且打印 emoji 的 core 模块。

### 7.1 重跑某一步的通用手法

因为「存在即跳过」，想重跑必须**先删产物**：

| 想重跑 | 删除 |
| --- | --- |
| 转写 | `output/log/cleaned_chunks.xlsx` + `.cache/asr/`（**只删 xlsx 不够**：缓存命中会立刻重建它，见 7.5） |
| NLP 切分 | `output/log/sentence_splitbynlp.txt`、`output/log/sentence_splitbymeaning.txt` |
| 翻译 | `output/log/translation_results.xlsx`（+ 必要时 `output/gpt_log/*.json`） |
| 字幕生成 | `output/*.srt`、`output/log/subtitle_stage_done.txt` |
| 字幕润色（step5.2，可选） | 不必删：产物 `output/log/translation_results_polished.xlsx` 每次重跑都覆盖（该步无幂等检查）。⚠️ 改过润色提示词后要一并删 `output/gpt_log/polish_subs.json`（以及 `polish_audit.json`），否则会命中缓存复用旧结果；若关过思考，那一档的缓存另有分区 `polish_subs_nothink.json` / `polish_audit_nothink.json`，改提示词也要删（**切换思考开关本身不需要删**：换的就是分区名，立即生效） |
| 压制 | `output/output_sub.mp4`（并删完成标记，否则 UI 仍显示已完成） |
| 全部 | UI 上「删除并重新选择」按钮（会 `shutil.rmtree("output")`），或手动删 `output/`（**不含** `.cache/asr/`） |

### 7.2 清 LLM 缓存（改提示词后必做）

```powershell
Remove-Item output\gpt_log\*.json
```

`output/gpt_log/<log_title>.json` 同时是**缓存**：`ask_gpt` 用 `(model, prompt)` 精确匹配历史记录并直接返回旧结果。改了 `core/prompts_storage.py` 却"没效果"，九成是这个原因。

> ⚠️ 历史上磁盘上可能残留一个 `output/gpt_log/None.json`——它会让「API 密钥检查」命中缓存假通过。现在 `log_title=None` 不再写该文件，遇到时直接删掉即可。

### 7.3 清火山 ASR 二级缓存（改火山参数后必做）

```powershell
Remove-Item -Recurse output\log\asr_results
```

火山路径有**第二级缓存**（`output/log/asr_results/volcano_asr_*.json`）。改了 `volcano_asr.*` 参数后，除了删 `cleaned_chunks.xlsx` 还要删这个目录，否则会命中旧结果。UI 上也提供了「清空 ASR 结果缓存」按钮（检测到缓存时出现在字幕区块下方）。

### 7.4 观察 LLM 交互

- `output/gpt_log/<log_title>.json` —— 每个 log_title 一个文件，数组结构，含 `model` / `prompt` / `response` / `message`。
- `output/gpt_log/error.json` —— 解析失败或业务校验失败的原始返回（**校验失败也会写这里**，且 `message` 是真实的业务错误，不再是误导性的 "json_repair parsing failed"）。
- log_title 与步骤对应关系见 [`../03-subsystems/01-LLM调用与提示词.md`](../03-subsystems/01-LLM调用与提示词.md)。

### 7.5 清转录缓存 `.cache/asr/`（改了 ASR 相关设置后必做）

```powershell
Remove-Item -Recurse .cache\asr
```

这是**第一级也是唯一跨 `output/` 清理存活**的 ASR 缓存（`core/all_whisper_methods/transcription_cache.py`，目录 `.cache/asr/<key>/<part>.json`）：

- 键的组成：源媒体**内容** md5 + `whisperx`/`faster-whisper`/`demucs` 版本 + `asr_engine`/`model`/`language`/`demucs`（火山再加 10 个 `volcano_asr.*` 参数）。
- `part` 为 `complete`（整条结果）或 `f"{start:.2f}_{end:.2f}"`（分段结果）。`complete` 命中时 **连 Demucs 都跳过**；只有部分分段命中时逐段复用，只补缺的段。
- 因此「删了 `cleaned_chunks.xlsx` 却还是旧结果」「改了模型/语言但没重跑」基本都是它。UI 上对应「♻️ 转录缓存（N 个条目）」里的「清空转录缓存」按钮；`whisper.cache: false` 可整体关闭（默认 `true`）。
- 它**不会**被「归档到历史记录」或 `shutil.rmtree("output")` 清掉，这是刻意设计——避免清一次产物就重复付费识别。

## 九、常见现象速查（详细版见 05-guides/05）

| 现象 | 最可能原因 | 处置 |
| --- | --- | --- |
| 改了提示词但输出没变 | `output/gpt_log/*.json` 缓存命中（缓存键含 model + prompt） | 删缓存 json |
| 改了火山 ASR 参数但输出没变 | `output/log/asr_results/` 二级缓存命中 | 删该目录（或用 UI 按钮） |
| 删了 `cleaned_chunks.xlsx` 但转写结果照旧 | `.cache/asr/` 转录缓存命中（`complete` 命中时连 Demucs 都跳过） | 删 `.cache/asr/`，或用 UI「清空转录缓存」；`whisper.cache: false` 可整体关闭 |
| 改了 TOS / `volcano_asr.app_id` 等设置但结果没变 | 这些键**不参与**缓存身份（身份只有源媒体内容 + `asr_engine`/`model`/`language`/`demucs`，火山再加 10 个参数） | 若确实需要重跑，删 `.cache/asr/` |
| 改了参数但某步没重跑 | 该步产物已存在（幂等跳过） | 删对应产物 |
| `output/` 下有多个视频文件 | `find_video_files` 会取最新的一个并告警 | 归档或移走多余文件 |
| 对齐报错或时间轴错乱 | `cleaned_chunks.xlsx` 文本与句子文本不一致 | 确认下游是否正确 `strip('"')`；把 `subtitle.align_on_mismatch` 设为 `strict` 可让问题立即暴露而非兜底 |
| LLM 请求全部失败 | `api.key` 为空 / base_url 拼接问题 | 见 [`../03-subsystems/01-LLM调用与提示词.md`](../03-subsystems/01-LLM调用与提示词.md) |
| 提示词/断句用了旧语种 | 已修：源语言统一走 `get_source_language`，`update_key("whisper.language", ...)` 会同步 `detected_language` | 在侧边栏重选一次识别语言；跑 `tests/test_source_language.py` |
| 转写极慢 | 落在 CPU（无 CUDA 或驱动异常） | 看启动日志 `device: cpu`；`python installer.py --check` 会打印 torch 版本与 CUDA 可用性 |
| 启动直接报错/看不到原因 | 缺包、缺 ffmpeg/ffprobe 或端口被占用 | 先 `python launch.py --no-log` 看预检结论，再 `python installer.py --check`；运行日志在 `logs/videolingo_<时间戳>.log` |
| 装了依赖但启动仍报缺模块 | 安装状态指纹（`.videolingo-install.json`）认为环境已一致而跳过安装 | `python installer.py --force` |
| 音频输入跑完没有 `output_sub.mp4` | 预期行为：音频输入跳过压制，只交字幕 | `cat output/input_manifest.json` 看 `type` 是否为 `audio` |
| 界面按钮文字看不清 | 侧边栏与主区域的按钮配色 CSS 冲突 | 见 [`../05-guides/04-已知问题与技术债.md`](../05-guides/04-已知问题与技术债.md) R4 |
| 没有成片可预览 | 侧边栏 **烧录字幕（压进成片）** 处于关闭状态 | 打开它并重跑 step7；输入为音频时不产出成片（预期） |
| 打开页面就报 `TypeError: ... unexpected keyword argument` | streamlit 版本与代码中的控件参数名不匹配 | `pip show streamlit` 核对版本；见技术债 G4 |
