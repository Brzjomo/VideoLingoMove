# 术语与概念表

这个项目里"segment / chunk / sentence / line / subtitle" 都被用过，且**含义随上下文变化**。读代码或改代码前先对齐口径，能避免大部分误解。

---

## 一、数据粒度（从细到粗）

| 术语 | 代码中的载体 | 定义 | 谁产生 / 谁消费 |
| --- | --- | --- | --- |
| **word（词）** | `output/log/cleaned_chunks.xlsx` 一行 | WhisperX 对齐后的最小单位，含 `start`/`end`（秒）。中文场景下一个"词"可能是 1~2 个字 | 产生：`process_transcription`；消费：`step6 align_timestamp` |
| **ASR segment（识别段）** | 内存中的 `result['segments'][*]` | WhisperX 原生输出的话段，含 `words` 列表。**不落盘**，只在 `step2` 内部使用 | `transcribe_audio_with_whisper` |
| **audio segment（音频切片）** | 内存中的 `List[Tuple[float, float]]` | `split_audio` 把长音频按静音点切成的时间区间列表，用于避开 Whisper 25MB 限制 | `split_audio` → 逐段转写 |
| **sentence（句子/行）** | `sentence_splitbynlp.txt` / `sentence_splitbymeaning.txt` 一行 | NLP + LLM 按"句意"重切后的文本单元，**是翻译与时间轴对齐的基本单位** | 产生：`step3`；消费：`step4`、`step5`、`step6` |
| **translation chunk（翻译块）** | 内存字符串（`split_chunks_by_chars` 的结果） | `step4_2` 把若干句子打包成 ≤600 字符 / ≤10 行的块，一次发给 LLM（`core/step4_2_translate_all.py`） | `translate_all` |
| **subtitle（字幕条）** | `output/trans.srt` 的一个 block | 最终显示单位，满足**按语言档位的单行上限**（`subtitle.max_length`，单位=显示宽度；含 `GRACE = 1.15` 宽容量，见「档位」一条） | 产生：`step6`；消费：`step7`（压制）、`download_subtitle_zip_button`（打包） |

> ⚠️ 两种 "chunk" 含义完全不同：`cleaned_chunks` 是**词级**、`translate_chunk` 是**翻译批次**。看到 chunk 先确认上下文。

## 二、字幕压缩相关（`core/subtitle_trim.py`）

| 名称 | 类型 | 定义 | 代码位置 |
| --- | --- | --- | --- |
| `min_trim_duration` | config | 字幕时长**超过**它才做"按朗读时长压缩"；否则原样保留 | `core/step4_2_translate_all.py` |
| `speed_factor.max` | config `speed_factor.max` | 允许的最快语速倍率（默认 1.4）。压缩判断时先把预估时长**除以它**——只有在最快语速下仍超时才需要真正删减内容 | `core/subtitle_trim.py` |
| `estimated_duration` | 局部变量 | `estimate_duration` 给出的音节级朗读时长估算（秒），已被 `speed_factor.max` 折算 | `core/subtitle_trim.py` |
| `llm_sentence_split` | config | 是否用 LLM 优化断句。**只在 `transcription_only = true` 时生效**；翻译模式下强制为 `true`。关闭时 `step3_2` 直接输出 spaCy 结果、`step5` 用 `subtitle_split.split_at_boundaries` 按**句法边界**切（硬边界标点 → 日语接续/助词 → 拉丁连接词，窗口 `subtitle.boundary_window`），零 LLM 调用 | 判定：`core/config_utils.use_llm_sentence_split`；执行：`core/step3_2_splitbymeaning.py`、`core/step5_splitforsub.py` |
| `identical_src_trans` | 局部变量 | `step5` 里判断 `Source` 是否等于 `Translation`（直通模式为真）。为真时跳过 `align_subs`——那个调用等于让 LLM 把文本与它自己对- 齐 | `core/step5_splitforsub.py` |
| `ESTIMATOR` | 模块级单例 | `AdvancedSyllableEstimator` 实例，首次调用时惰性创建（`G2p` 加载较慢） | `core/estimate_duration.py` |

> 📌 `speed_factor` 里原本还有 `min` / `accept` 两项，仅服务于已删除的配音变速，已从 `config.yaml` 移除，现只剩 `max`。

> 📌 历史上还有一整节「配音阶段专有名词」（`gap` / `tolerance` / `tol_dur` / `est_dur` / `real_dur` / `if_too_fast` / `cut_off` / `new_sub_times` / `dub_volume` / `min_subtitle_duration` 等），那是已删除的 step8~step12 链路独有的列与配置。若需查阅，看 git 历史中重写前版本的本文档。

## 三、LLM / 提示词相关

| 名称 | 含义 | 位置 |
| --- | --- | --- |
| `log_title` | `output/gpt_log/<log_title>.json` 的文件名，同时是**缓存分区键**；传 `None` 或 `'None'` 表示不写日志也不读缓存 | `ask_gpt(prompt, ..., log_title=...)` |
| `valid_def` | 调用方传入的校验回调，返回 `{"status": "success"/"error", "message": str}`；`error` 会触发重试并写入 `error.json`，且失败原因会被**回注给模型** | `core/ask_gpt.py` |
| `use_cache` / `bypass_cache` | `use_cache=False` 完全不读写缓存（连通性检查用）；`bypass_cache=True` 只跳过**读取**、仍写回结果（重试用，替代了旧的 `prompt + ' ' * retry` 技巧） | `core/ask_gpt.py` |
| `[br]` | 提示词里约定的切分标记（"break"），LLM 用它在长句中标注切点 | `get_split_prompt`、`get_align_prompt` |
| `analysis` | 多个提示词要求的"先分析再输出"字段，仅用于提升 LLM reasoning 质量，不被代码消费 | `get_split_prompt`、`get_subtitle_trim_prompt` 等 |
| `split1` / `split2` / `assess` / `choice` | **断句提示词的双候选契约**：模型给出两种切法、比较后自选一种（`choice` 为 `"1"`/`"2"`）。消费端 `split_sentence` 校验 `choice` 合法、`split{choice}` 存在且含 `[br]` 后才取该键；单候选的旧键 `"split"` 已不存在 | `core/prompts_storage.py: get_split_prompt`、`core/step3_2_splitbymeaning.py: split_sentence` |
| `get_source_language` | 源语言的**唯一判定点**：`whisper.language` 非空且非 `auto` 时一律以它为准，否则回退 `whisper.detected_language`，两者都不可用则抛 `ValueError` | `core/config_utils.py`；调用点见 `prompts_storage.py`（5 处）、`spacy_utils/load_nlp_model.py`、`split_by_mark.py`、`split_long_by_root.py`、`step3_2`、`step5` |
| `origin` / `direct` / `reflection` / `free` | 三步翻译的四个字段：原文 / 直译 / 反思 / 意译。**只有 `free` 会进入最终字幕**（`reflect_translate: false` 时用 `direct`） | `core/prompts_storage.py`、`core/translate_once.py` |
| `shared_prompt` | 拼装出的上下文包：前文 3 行 + 后文 2 行 + 术语注记 | `translate_once.translate_lines` |
| `things_to_note` | 命中当前文本的术语列表（`src`/`tgt`/`note`） | `step4_1 search_things_to_note_in_prompt` |
| `topic` | `terminology.json` 里的视频主题（提示词要求输出 `topic`）。早期代码误读 `theme` 导致主题上下文恒为空，已统一为 `topic`。上游 3.x 把该键改成了 `theme`，**本分支故意不跟**——跟了会让主题上下文重新恒为 `None` | `core/prompts_storage.py`、`core/step4_1_summarize.py`、`core/step4_2_translate_all.py` |
| `align_on_mismatch` | `subtitle.align_on_mismatch`：`warn`=精确匹配失败时模糊兜底并告警（默认）；`strict`=失败即抛错 | `core/step6_generate_final_timeline.py` |
| **轻改写（B 方案）** | 允许 LLM 在 step5 的**切点处**只修**衔接**：移动边界、把一个虚词挪到另一侧、删掉会孤零零留在切点上的连接词、最多补一个**虚词/助词**；**绝不把裸从句补成完整句**（字幕是跨条连读的，要求"每行自足"只会逼模型补主语/宾语/谓语并跨行重复同一句语义）。开关 `subtitle.align_allow_rewrite`（默认 `true`，唯一判定点 `core.config_utils.align_allow_rewrite`）**同时**切换提示词与校验：开=提示词用 `_ALIGN_RULE3_LIGHT`，校验拦五类结果 —— 段数 < 2 / 空段 / 孤立碎片；**段首悬空助词**（`dangling_start`：を/の/的）；长度比超出 `(0.8, 1.3)`；重复（`同时同时`，或原文已有的说法在拼接里变多）；token 覆盖率 < 0.85；关=提示词换 `_ALIGN_RULE3_STRICT`（一个字都不许动），校验要求拼接**逐字等于**整句译文。**移动边界两档都允许**（否则悬空切点无解），段首悬空助词也是两档都拦 | `core/prompts_storage.py: get_align_prompt`（第 3 条两版）、`core/subtitle_split.py: check_align_parts` / `dangling_start`、`core/step5_splitforsub.py: align_subs` |
| **字幕润色（step5.2）** | step5 与 step6 之间的**可选**一步：把 step5 切好的每条字幕译文**只改措辞**（语序/连接词/语气助词），不改信息、不改行数、不动 `Source`。**默认关**（`subtitle.polish_translation`，判定点 `core.config_utils.polish_translation`，缺键/读失败都按关），要用户在侧边栏「✨ 字幕润色（可选，会额外调用 LLM）」里显式打开。成本：每 20 行一次 `polish_subs` 调用 + 对确实改动过的行每个批次一次 `polish_audit` 审校。护栏 `core/subtitle_split.polish_ok`（空行/超档位/变长/长度比/覆盖率/丢数字/重复 → 该行保持原译文；审校判为改了信息的行回退原译文）；产物 `output/log/translation_results_polished.xlsx`，step6 只在开关打开且行数一致时才读它。面板里还有**两个取舍开关**（默认值合起来就是"最忠实也最贵"）：`subtitle.polish_thinking`（默认 `true`，**只管润色调用**：关掉则 `ask_gpt(extra_body={"thinking": {"type": "disabled"}})` 省约 91% token（只省润色那部分），但覆盖率门槛自动从 0.70 收紧到 0.85、回退更多行；润色因此按档位换缓存分区 `polish_subs[_nothink]`，所以切换立即生效 —— **审校调用 `_audit_info_changes(pairs, stats)` 不带这个参数**，恒按模型默认档（思考开）跑、恒落 `polish_audit` 分区，因为它是兜住"换词式增补"的安全网且很便宜：实测一次 3 行 ≈ 860 tokens）与 `subtitle.polish_long_lines_only`（默认 `false`，打开则只润色宽度 ≥ 15 显示宽度且含分句标点的长行，其余行原样保留） | `core/step5_2_polish_subs.py`、`core/subtitle_split.py: polish_ok` / `needs_polish_long_line`、`core/prompts_storage.py: get_polish_prompt` / `get_polish_audit_prompt`、`core/ask_gpt.py: ask_gpt(extra_body=…)`、`core/step6_generate_final_timeline.py: pick_translation_file` |
| **显示宽度（display width）** | 字幕长度的**统一度量单位**：中日文一字 1.75、韩文 1.5、泰文 1、全角符号 1.75、其余 1。`subtitle.max_length`、各语言档位、孤立碎片阈值都用它；机械断行按字符计数时用 `chars_cap()` 换算。实现只有一处：`subtitle_limits.measure`（`step5.calc_len` 是它的同名包装） | `core/subtitle_limits.py`、`core/step5_splitforsub.py: calc_len` |
| **档位（length profile）** | 每个语言一组 `(单行上限[显示宽度], 粗切词数[spaCy token])`，见 `LENGTH_PROFILES`（中日 60/30、韩 48/28、拉丁 70/26、俄与 RTL 65/26、泰 65/20；兜底 70/26），另留 `GRACE = 1.15` 宽容量。开关 `subtitle.auto_length_by_language`（默认 `true`）：开=切语言即覆盖 `subtitle.max_length` / `max_split_length` 且**运行期按当前语言现算**；关=按手填值走 | `core/subtitle_limits.py`、`core/config_utils.py: auto_length_by_language` |
| `transcription_only` | "仅转录"直通模式：跳过 `step4_1`，把源文当译文写入 `translation_results.xlsx` | `config.yaml`、`step4_2_translate_all.py` |

## 四、ASR / 音频处理相关

| 名称 | 含义 | 位置 |
| --- | --- | --- |
| `ASR engine` | 语音识别引擎选择，`whisper`（本地 WhisperX）或 `volcano`（火山引擎在线 ASR） | `config.yaml: asr_engine` |
| `Belle 模型` | `Huan69/Belle-whisper-large-v3-zh-punct-fasterwhisper`，中文带标点的 faster-whisper 模型；`whisper.language == 'zh'` 时**强制**使用 | `core/step2_whisperX.py: load_whisper_model_name` |
| `VAD` | Voice Activity Detection，WhisperX 内部用它跳过静音；参数 `vad_onset=0.5`、`vad_offset=0.363` | `core/step2_whisperX.py` |
| `demucs` | 人声/伴奏分离模型（可选）。开启后转写用 `vocal.mp3`（人声，语音更干净） | `core/all_whisper_methods/demucs_vl.py` |
| `Demucs 双轨` | `output/audio/vocal.mp3`（人声）与 `output/audio/background.mp3`（其余所有声部求和）。配音链路删除后 `background.mp3` 已无消费者，但 `demucs_main` 仍会一并产出 | `core/all_whisper_methods/demucs_vl.py` |
| `TOS` | 火山引擎对象存储（Torch Object Storage）；火山 ASR 需要先把音频上传到 TOS 拿到可访问 URL。**本项目唯一的 TOS 实现**是 `core/all_whisper_methods/tos_service.py`（单例入口 `get_tos_service`）；批量场景的能力已合并进它 | `core/all_whisper_methods/tos_service.py` |
| `ITN` | Inverse Text Normalization，把"二零二四年"转成"2024年"；火山 ASR 参数 | `config.yaml: volcano_asr.enable_itn` |
| `DDC` | 火山 ASR 的语义顺滑（Disfluency/Disorder Correction）参数 | `config.yaml: volcano_asr.enable_ddc` |
| `for_whisper.mp3` | 为 WhisperX 准备的转写输入音频（16 kHz / 96 kbps / 单声道）。**只有 `asr_engine=whisper` 时才生成**——批处理的预处理缓存清单据此区分（见 `required_preprocess_files`） | `whisperX_utils.compress_audio` |
| `input_manifest.json` | 「本次要处理的是哪个文件、它是音频还是视频」的清单，写在 `output/input_manifest.json`，内容 `{"path", "type"}`（`type` ∈ `video`/`audio`）。下载完成与上传落盘后各写一次；`find_media_file` **优先读它**，读不到才按扩展名回退 | `core/step1_ytdlp.py: write_input_manifest`/ `read_input_manifest`/ `find_media_file`、`st_components/download_video_section.py` |
| `find_media_file` | 定位源媒体的统一入口，返回 `(路径, 媒体类型)`，类型为 `video` 或 `audio`。`is_audio_only_input`（`core/step1_ytdlp.py`）是它的薄封装 | 消费者：`core/step2_whisperX.py: transcribe`、`core/step7_merge_sub_to_vid.py`、`core/onekeycleanup.py: cleanup`、`download_video_section` |
| `转录缓存（transcription_cache）` | 内容寻址的 ASR 结果缓存，落在 **`output/` 之外** 的 `.cache/asr/<key>/<part>.json`。`part` 为 `complete` 或 `f"{start:.2f}_{end:.2f}"`；键 = 源媒体内容 md5 + `schema` + whisperx/faster-whisper/demucs 版本 + `asr_engine`/`model`/`language`/`demucs`（火山再加 10 个 `volcano_asr.*` 参数）。`complete` 命中时连 Demucs 一起跳过 | `core/all_whisper_methods/transcription_cache.py`（`cache_key`、`read_result`、`write_result`、`clear_cache`）；读写方 `core/step2_whisperX.py: transcribe`，设置来自 `_asr_cache_settings` |
| `black_screen.mp4`（历史产物） | **不再产生**：早期上传音频时会被包成黑底视频（640×360 + 完整音频），现已改为写 `input_manifest.json`。`core/step1_ytdlp.py: is_audio_placeholder` 仍认这个名字，`step7` 在 `resolution=0x0` 时把它原样保留为 `output_sub.mp4`，所以旧目录仍然可用（批处理侧 `batch/utils/batch_processor.py: convert_audio_to_video` 仍是同样的思路，文件名变成了 `<原名>.mp4`） | `core/step1_ytdlp.py`、`core/step7_merge_sub_to_vid.py` |

## 五、流程与状态相关

| 名称 | 含义 |
| --- | --- |
| **幂等跳过** | 每个 step 开头检查自己的产物文件是否存在，存在即 return。是"断点续跑"的实现方式 |
| **阶段完成判据** | `output/log/subtitle_stage_done.txt`（由 `step7` 写）。早期用 `output/output_sub.mp4` 是否存在判断，但"烧录字幕关闭"或"输入是音频"时都不产出成片，那个判据会永远为假 |
| **烧录字幕（压进成片）** | 侧边栏开关（2026-09-20 前叫 `Burn-in Subtitles`）；**以 `resolution` 表达**：开 → `1920x1080` / `640x360`，关 → `'0x0'`。关闭时只出字幕、不做压制（静默跳过） |
| **TaskRunner** | 在后台线程里顺序执行 `[(标签, 无参可调用对象)]` 的任务执行器（`st_components/task_runner.py`）。`state` 六态：`idle` / `running` / `paused` / `stopped` / `completed` / `error`；`progress` = `(current_step+1)/total_steps`。`st.py` 用 `TaskRunner.get(st.session_state, RUNNER_KEY)` 取单例，`build_task_steps`（`st.py`）负责组装步骤表，`task_control_panel`（`st.py`，`@st.fragment(run_every=1)`）每秒刷新进度条与暂停/继续/停止按钮 |
| **TaskRunner.check_cancel** | core 侧长循环的协作式取消钩子（`st_components/task_runner.py`）：暂停时在 `_pause_event` 上阻塞，收到停止请求时抛 `StopTask`；没有活跃 runner（命令行单跑）时是空操作。core 侧包装为 `easy_util.check_cancel`（`easy_util.py`，惰性导入避免 `core/` 依赖 Streamlit） |
| **TaskRunner.request_review_pause** | 由步骤自己（worker 线程内）请求的"等待人工确认"暂停（`st_components/task_runner.py`），会置 `paused_for_review = True`，UI 据此渲染术语确认界面而非普通暂停条。调用点：`st.py: step_summarize`（`pause_before_translate: true` 时） |
| **StopTask** | 用户请求停止时由 `check_cancel` 抛出的异常（`st_components/task_runner.py`）；`TaskRunner._run` 捕获它并把状态置为 `stopped`，不会当成 error |
| **归档 / cleanup** | `core/onekeycleanup.py: cleanup(dir)` 把 `output/` 内容搬到指定目录：单次模式为 `history/<视频名>/`，批处理为 `batch/output/<视频名>/`。**不含** `.cache/asr/`（转录缓存刻意留在原处） |
| **批处理归档前移** | 每次点「开始批量处理」时，上一批的 `batch/output/` 会被改名为 `batch/output_archive_<时间戳>/` 而不是删除 |
| **占位视频（已移除）** | 历史上 `resolution: '0x0'` 会无条件生成 1 秒黑帧。现在：真实视频不生成任何成片，**音频输入在 `step7` 更早处就返回**，只有旧路径遗留的 `black_screen.mp4` 会被原样保留为成片 |

## 六、文件命名约定

| 模式 | 含义 |
| --- | --- |
| `output/log/*` | 步骤间交换的结构化中间产物（xlsx / txt / json / srt） |
| `output/log/subtitle_stage_done.txt` | 字幕阶段完成标记（`step7` 写，UI 读） |
| `output/log/asr_results/*.json` | 火山 ASR 的二级结果缓存；调过火山参数后需清理（UI 有按钮） |
| `output/gpt_log/<log_title>.json` | LLM 交互记录 + 缓存 |
| `output/audio/*` | ASR 相关音频：`raw.wav` / `raw.mp3` / `for_whisper.mp3` /（可选 demucs 的 `vocal.mp3`、`background.mp3`） |
| `output/*.srt` | 最终字幕：`src`（源）/`trans`（译文）/`src_trans`（源上译下）/`trans_src`（译上源下） |
| `<视频名>.srt` / `<视频名>.txt` | 与源视频同名的"默认字幕"与转录文本。**内容来源按模式区分**：翻译模式取 `trans_src.srt`（双语），仅转录模式取 `src.srt`（只有原语言）；缺失时各有兜底退回。单次模式写在 `output/`，批处理模式额外复制到**输入视频所在目录**（作为"已翻译"判据） |
| `output/input_manifest.json` | 输入清单：`{"path", "type"}`，标记本次处理的是哪个源文件、它是 `video` 还是 `audio` |
| `output/output_sub.mp4` | 字幕成片（仅烧录字幕开启**且输入是视频**时产出；音频输入跳过压制） |
| `translate_<step_name>.json` | 三步翻译的 log_title：`translate_faithfulness` / `translate_expressiveness` |
| `.cache/asr/<key>/<part>.json` | 内容寻址的转录缓存（`<part>` = `complete` 或 `f"{start:.2f}_{end:.2f}"`）。**在 `output/` 之外**，删 `output/`、归档都不影响它 |
| `logs/videolingo_<时间戳>.log` | `launch.py` 每次启动写一份的运行日志（stdout + stderr 合并） |
| `history/<原名>/`、`batch/output/<原名>/` | 归档目录，内部结构与 `output/` 对应 |
| `batch/output_archive_<时间戳>/` | 批处理「上一批产物」的自动归档（重复点开始时产生） |
