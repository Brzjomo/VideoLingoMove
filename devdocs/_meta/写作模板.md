# devdocs 文档写作模板（所有 devdocs 文档必须遵守）

> 本文件是 `devdocs/` 下所有文档的元规范。新增或改写任何 devdocs 文档前先读本文件。

## 1. 文件头（Front-matter）

每个文档开头使用如下 YAML front-matter（不要加代码块围栏）：

```yaml
---
title: 一句话标题
layer: 层次（见 README.md 的分层定义，如 01-overview / 02-pipeline / 03-subsystems / 04-interfaces / 05-guides）
source_files:
  - core/xxx.py
status: verified | draft
last_verified: YYYY-MM-DD
---
```

## 2. 正文结构

按需使用以下小节，顺序固定，不适用的可省略（不要留空标题）：

1. `## 一、职责与边界` —— 这段代码负责什么、不负责什么（2-5 句）。
2. `## 二、文件清单` —— 表格：文件路径 / 行数 / 主要职责。
3. `## 三、调用链与数据流` —— 上游谁调用它、它调用谁；用 Mermaid `flowchart` 或 ASCII 图表达。必须包含真实的函数名。
4. `## 四、关键数据结构` —— 输入/输出数据结构，写清字段名、类型、单位（秒/字符）。列出落盘的中间产物文件路径。
5. `## 五、逐函数/逐模块实现说明` —— 表格或小标题，写：函数签名、作用、关键实现细节、异常/回退行为、副作用（写文件、改 config.yaml、网络请求）。
6. `## 六、关键参数与配置` —— 与 `config.yaml` 的键路径一一对应。
7. `## 七、技术要点与坑` —— 非显而易见的设计、隐含假设、易踩的坑（含"改这里会影响谁"）。
8. `## 八、扩展点` —— 想新增/删减/优化功能时应该动哪些函数、需要注意什么。
9. `## 九、验证方式` —— 如何单独运行/复现这一段（真实命令或最小代码片段）。
10. `## 十、相关文档` —— 相对链接，指向上下游文档。

## 3. 写作要求（硬性）

- **事实必须来自真实代码**。禁止编造函数名、参数、文件名、config 键。写之前先读源文件全文。
- 引用文件路径时使用相对仓库根的形式（如 `core/step2_whisperX.py`），行号必须真实（格式 `core/step2_whisperX.py:112`）。
- 中间产物路径必须与代码一致（如 `output/log/cleaned_chunks.xlsx`）。
- 语言：简体中文。术语（函数名、字段名、config 键、库名）保留英文原文。
- 表格优先于长段落。段落每段不超过 5 行。
- 明确区分「现状」与「建议」：建议统一放在 `## 八、扩展点` 或 `> 💡 建议：` 引用块，不得混入描述现状的句子。
- 每个文档末尾必须有 `## 十、相关文档`，且链接使用相对路径（如 `../02-pipeline/02-转录.md`）。
- 不要写"本文档将介绍…"这类空话，直接给信息。
